## Francais

### Changements

**Une destination tapee ne peut plus heriter de l'approbation d'un profil**

- **Un profil importe ne peut plus occuper l'espace de noms des connexions rapides.** Quand vous
  tapez une destination dans la palette, Heimdall lui fabrique un identifiant interne et y range le
  certificat que vous approuvez pour elle. Un profil importe pouvait porter exactement le meme
  identifiant, car un import conserve celui que son fichier contient : approuver le certificat de
  ce profil autorisait alors la destination tapee a se connecter sans question, si les deux
  presentaient le meme certificat. La palette lui proposait aussi les actions d'une destination
  tapee au lieu de celles d'un profil enregistre.
- L'import attribue desormais un nouvel identifiant a un profil qui arrive dans cet espace. Le
  profil est importe et utilisable comme les autres ; seul son identifiant interne change.

**Un outil occupe ne bloque plus son propre nettoyage**

- **Fermer Heimdall arrete les outils externes en cours.** Un onglet d'outil refuse de se fermer
  tant que sa commande tourne, ce qui est juste quand vous fermez l'onglet vous-meme. A la sortie
  de l'application, ce refus n'avait plus de destinataire : le nettoyage de l'outil, qui interrompt
  la commande et arrete le processus, n'etait jamais atteint. Windows ne termine pas un processus
  enfant avec son parent, si bien qu'une commande longue survivait a l'application.

### Notes

- Cette version corrige deux defauts anterieurs a la v2026.090301 mais qui contredisaient ce que
  ses notes annoncaient : l'isolation des approbations entre destinations, et le fait qu'aucune
  session ne reste ouverte a la sortie. Les deux affirmations sont exactes a partir de cette
  version.

## English

### Changes

**A typed destination can no longer inherit a profile's approval**

- **An imported profile can no longer occupy the quick-connect identifier namespace.** When you
  type a destination into the palette, Heimdall builds it an internal identifier and files the
  certificate you approve for it under that identifier. An imported profile could carry exactly the
  same one, because an import keeps whatever identifier its file holds: approving that profile's
  certificate then let the typed destination connect without a question, if both presented the same
  certificate. The palette also offered it a typed destination's actions rather than a saved
  profile's.
- An import now assigns a fresh identifier to a profile arriving in that namespace. The profile is
  imported and usable like any other; only its internal identifier changes.

**A busy tool no longer blocks its own cleanup**

- **Closing Heimdall stops running external tools.** A tool tab refuses to close while its command
  is running, which is right when you close the tab yourself. At application exit that refusal had
  nowhere to go: the tool's cleanup, which cancels the command and stops the process, was never
  reached. Windows does not end a child process with its parent, so a long-running command outlived
  the application.

### Notes

- This version fixes two defects that predate v2026.090301 but contradicted what its notes stated:
  that approvals are isolated between destinations, and that no session is left open at exit. Both
  statements are accurate from this version onwards.
