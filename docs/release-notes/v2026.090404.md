### Changes

**A scheduled task no longer falls back to a profile with the same name**

- **Deleting the profile a task points at could move that task to another machine.** If two profiles
  share a display name - two called "Production", on two different servers - deleting the one a task
  names left the other as the only profile of that name, and the task connected to it. The previous
  version required the name to be unique before falling back, which is exactly the condition
  deleting the profile creates.
- A task that records a profile identifier is now answered by that identifier or not at all. A task
  that records no identifier, which only older task files do, is still answered by display name when
  exactly one profile carries it.

### Notes

- **What this costs.** A task whose profile was deleted and re-created stops running, because the
  re-created profile has a new identifier. Re-point the task at the profile you want. The scheduler
  records a task's last-run time before it runs, so such a task will still show a recent run in the
  Scheduled tab; the log says which task it was and which identifier could not be found.
- **A correction to the previous notes.** v2026.090403 stated that a scheduled task no longer
  connects to the wrong machine. With the target profile deleted, it still could. This version is
  what makes that statement true for the deletion case.
