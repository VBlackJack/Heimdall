A memory release. Three Remote Desktop sessions used to cost about a gigabyte; they now cost about
two thirds of that. The change is one setting, it is on the Remote Desktop pages, and you can put
it back the way it was in one click if your sessions feel different.

### Where the memory was going

A user reported that each Remote Desktop connection cost roughly 250 to 300 MB, and that three at
once came to about 1.2 GB. That was accurate, and the reason turned out to be a single property of
the Microsoft Remote Desktop control that Heimdall was leaving at its default.

With hardware-accelerated rendering on, the control builds a Direct3D device and a decoding context
**for every session you open**. That is why memory grew with the number of sessions, and why it
stayed high after a session had gone.

Measured on two Windows Server 2022 machines, three sessions at once, 1920x1080 in 32-bit colour:

| Three sessions | Before | Now |
|---|---:|---:|
| Memory committed | 1145.9 MB | **763.3 MB** |
| Windows handles | 3898 | **3058** |

383 MB and 840 handles, a third of the footprint, for the same three desktops on the same screens.

### What changed for you

**Hardware-accelerated rendering is now a setting, and it starts off.** You will find it under
Settings, on the Remote Desktop page, and on each server's own Remote Desktop tab if you want a
different answer for one machine.

Nothing else about your sessions changes. Same resolution, same colours, same compression, same
redirections.

### The part we did not measure, said plainly

Turning hardware rendering off moves decoding from the graphics card to the processor. On idle
desktops and on scrolling text we saw no difference worth reporting, both under half a percent of
one core. **We did not measure a session showing video or continuous animation**, because we could
not drive a repeatable moving picture into a test session.

So: if a session feels less smooth than it used to, that is the trade, and it is one checkbox away
from being undone. Switch hardware-accelerated rendering back on, for that one server or for all of
them. We would rather tell you where the uncertainty is than let you discover it.

### Also fixed

Boolean display properties of the Remote Desktop control were never actually written. The code that
set them only produced numeric values, so the control refused them, and the refusal was invisible
because nothing checked the answer. Every such write now reports whether it worked, and a failure
says which default is still in force.

### What to check first after updating

1. Open a Remote Desktop session. It should look exactly as before.
2. Open two more. Memory should sit noticeably lower than you are used to.
3. Work in a session for a few minutes, especially if what you do there moves a lot on screen.
4. If anything feels less smooth, switch hardware-accelerated rendering back on under Settings,
   Remote Desktop, and tell us. That report is worth having.

### Still to come

Closing every session does not give you back everything. Heimdall keeps up to two Remote Desktop
controls alive so the next connection is fast, and each one holds on to roughly 300 MB. The amount
is bounded, it does not keep climbing, but it does mean a quiet Heimdall sits higher than a freshly
started one. Giving those spare controls an expiry is the next piece of work; it touches how
sessions are created and destroyed, so it is getting its own release rather than riding along with
this one.
