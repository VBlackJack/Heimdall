# Updates no longer leave Heimdall closed over an apostrophe, and Windows PowerShell keeps its own modules

A small release of fixes. An update could fail to restart Heimdall when a path held a
typographic apostrophe, and the Windows PowerShell that Heimdall starts for updates
and service actions could load PowerShell 7's modules.

## An update no longer leaves Heimdall closed because of an apostrophe

PowerShell ends a quoted string on a typographic apostrophe, as some keyboards and
autocorrect produce, just as it does on a plain one, and Heimdall escaped only the
plain one. A Windows profile named like O'Brien but typed with a typographic
apostrophe made the update relauncher fail to start, which left Heimdall closed after
an update.

Every kind of single quote is now escaped, in the update relauncher and everywhere
else Heimdall builds a PowerShell command from a path or a name:

- Start, Stop and Restart in the Service Status Dashboard.
- The WinRM launch.
- The PowerShell cd command sent from a file path.
- Windows commands generated from the command library.

## Windows PowerShell runs on its own modules when started from PowerShell 7

When Heimdall was started from a PowerShell 7 session, the Windows PowerShell it
starts inherited PowerShell 7's module directories and ran on PowerShell 7's modules,
a combination neither PowerShell supports.

- **Updates.** The Windows PowerShell that installs an update now gets the inherited
  module path without PowerShell 7's entries, every other entry kept, as the WinRM tab
  already does. The installer's signature and SHA-256 checks ran in either case.
- **Service Status Dashboard.** The service listing runs with the same module path.
- **Start, Stop and Restart of a service.** These run in an elevated Windows
  PowerShell, which loaded PowerShell 7's Management module for the service command.
  Its script now sets the same module path before anything else runs.
