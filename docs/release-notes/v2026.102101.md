# Shared sessions a team can use on day one, a command library in your language with runbooks, and a copy of the terminal that keeps its secrets

This release makes a shared MobaXterm file usable by a whole team the day it is added: five
session types are loaded, every session that is not is listed with its reason, and each person's
passwords are remembered on their own computer. The Command Library is rewritten in English with
its French beside it, knows the session it was opened from, captures a command from the terminal,
and chains steps into runbooks. And every terminal session can copy what it printed with its
secrets masked.

## Shared MobaXterm sessions

- **Five session types.** SSH and RDP were loaded already; Telnet, VNC and SFTP sessions now are
  too. The one-time MobaXterm import in Settings brings them as well.
- **Every skipped session says why.** FTP (sends the password in clear, not imported yet), WSL (a
  Linux system on the MobaXterm computer, nothing to connect to), the other types, and the sessions
  whose route Heimdall cannot follow: a Telnet or VNC session through an SSH jump host, an SSH,
  Telnet, VNC or SFTP session through a proxy, and an RDP session that signs in to its RD Gateway
  with a smart card. Each is listed in the import report and in the Settings import summary with
  its reason, instead of being loaded as a direct connection that would go around the bastion, the
  proxy or the gateway.
- **RD Gateway carried over.** An RDP session set to always use its RD Gateway and signing in to
  it with a password keeps that gateway: Heimdall connects through it. The gateway login is not
  carried over. A session set to Never or Detect connects directly, as it does in MobaXterm.
- **SFTP passwords remembered per user**, like SSH passwords: the same "Remember this password on
  this computer" box, the same rules, and forgotten when the server refuses it.
- **VNC passwords typed and remembered.** A shared VNC session whose server asks for a password
  was a dead end. The session now waits with "This VNC server asks for a password" and offers
  **Enter password**, with the same Remember box. The connection stays open while you type, so a
  server such as TigerVNC does not count a failed sign-in and block your address. A refused
  password is forgotten and the question offered again. One overlay carries the message, where two
  were stacked before.
- **Import report.** Duplicate hosts compare host and protocol: an SSH and an RDP session to one
  host are two ways to use it, not duplicates. Gateway outliers only count session types that can
  name a jump host in MobaXterm.
- **Limits written down** in the guide: a shared RDP session asks for its password in the Windows
  Security prompt and Heimdall does not remember it (file it in the external credential provider
  under the host name); network tools go through your own gateways, not through a shared bastion;
  the remote start folder of an SFTP session is not carried over; a Telnet session asks for its
  login in the terminal; a VNC server that also asks for a username stays out of reach.

## Command Library

- **The catalogue in your language.** The shipped actions and their categories show in the
  interface language, and a language switch reloads the library keeping the selected action. The
  catalogue is written in English with its French beside it; Spanish shows the English text for
  now. Categories are stable keys under the hood, so the search finds an action by its localized
  category label, and an export taken before this release imports into the current categories.
- **A catalogue that follows the installed version.** When an update changes the shipped
  actions, they are replaced at the next launch; your own actions, and the favorites and history
  of actions still shipped, are kept. Ten near-duplicate actions were merged into one each
  (lsblk, curl -I, du -sh, chown, chmod, traceroute, dig): a favorite on one of the ten removed
  ids is lost.
- **527 shipped actions, Linux and Windows.** 95 new actions fill the gaps: on Linux, nginx and
  Apache, SSH keys, accounts and expiry, firewalld, nftables and ufw, NetworkManager, time and
  host name, kernel modules and sysctl, swap, SMART, mdadm, LUKS, NFS and SMB shares, realm, SSSD
  and LDAP, auditd, SELinux and AppArmor, OpenSSL and certbot, libvirt and kubectl; on Windows,
  WinRM, hotfixes, TCP connections, IP configuration and the firewall, DHCP, DFS, failover
  clusters, shadow copies, disks and SMB, the registry, CIM, event levels and printing. Commands
  that need root start with `sudo`, flag parameters became choices, every shipped default
  generates (four did not), and the examples that did not fit their action are gone.
- **Workstation debloat pack.** The 72 actions that strip a personal Windows workstation (store
  apps, Edge, OneDrive, telemetry) ship apart from the catalogue, in
  `data\packs\windows-workstation-debloat.json` in the installation folder. Import that file with
  the library's Import button if you want them. They are aimed at a workstation, not a server;
  their text is French only for now; and nine of them open with a command-length error until
  their scripts are rewritten.
- **The library knows the session it was opened from.** The platform filter starts on the
  session's platform, a host parameter is prefilled with the session's host and a user parameter
  with its user name, and each row shows its command under its title. A profile can declare the
  operating system of its far end (General tab, **Operating system of the far end**): Windows or
  Linux is taken as given, and Automatic keeps the guess from the protocol, so SSH into a Windows
  OpenSSH server gets the Windows template. Post-connect steps follow the same declaration.
- **Insert** (Shift+Enter), between Copy and Send, types the command at the terminal's prompt
  without running it, so you can read and edit it and press Enter yourself. It never asks the
  dangerous-command confirmation, because nothing runs.
- **History knows where a command went.** Each entry records the host of the session and whether
  the command was sent or only copied; a **This host only** box, ticked when the library belongs
  to a session, shows only what went to that host. Sent means the text reached the terminal, not
  that it succeeded: a terminal gives nothing back, so no exit code is recorded.
- **Capture a command from the terminal.** Select a command in an SSH, Telnet, WinRM or local
  shell session and press **Ctrl+Shift+L**, or Shift+right-click and choose **Save selection to
  Command Library**. The editor for a new action opens, in the library tab already open if there
  is one, with the command in the pattern of the session's platform, the risk at Run, the
  protocol as a tag and the title left for you. A selection over several lines becomes one line,
  joined with `;` for Windows and `&&` for Linux, for you to read before saving. A plain
  right-click still pastes.
- **Runbooks.** A runbook chains the steps you would otherwise send one by one on every incident,
  such as status, logs, restart, status. The **Runbooks** button in the library header lists
  yours, with New, Edit, Duplicate, Delete and Run. A step is a library action with a value for
  each parameter, or a command typed as is for one platform; a value written `{{name}}` takes a
  variable the run asks for once at the start, prefilled from the session's host and user. The
  run is manual, step by step: the panel shows each step with its status and the current command,
  with **Send to Terminal**, **Insert**, **Copy**, **Skip** and **Stop**. A terminal returns no
  exit code, so you read the output, then send the next step or stop. Send asks the
  dangerous-command confirmation for a dangerous action and always for a literal step. Runbooks
  are your own data: none ships with Heimdall, and export, import and Git synchronization carry
  them with your actions.
- **Export asks what to include**: **My actions** (the default: what you created or imported, and
  your runbooks), **Current filter** or **Everything**, the seeded catalogue included.
- **Git synchronization** no longer refuses an action flagged Run or Dangerous, and a template
  with a choice, a number or a drive letter parameter now survives a round trip.
- **Fewer false refusals.** A value placed inside single quotes may hold shell characters (an
  LDAP filter, for example): the generator refuses them only where the quotes do not protect. A
  path is judged by its shape, not by where it points. Two validation messages that were English
  only are localized.

## Copy output, secrets masked

- **Ctrl+Shift+M** in an SSH, Telnet, WinRM or local shell tab, the session tab's menu, or the
  Ctrl+K palette. Heimdall reads the session's text (the last 4 MiB), masks the secrets it
  recognizes (private keys, authorization headers, URL credentials, key-value secrets such as
  `DB_PASSWORD=`, command-line passwords, AWS, GitHub and Slack tokens, JWTs, echoed password
  prompts) as `[masked:<rule>]`, and shows a preview with the count per rule and an option that
  replaces host names and IPv4 addresses with stable pseudonyms. Nothing reaches the clipboard
  until you press **Copy**.
- Runs on the machine, with no network and nothing written to disk. If a rule times out, nothing
  is copied. The command is absent on RDP, VNC, SFTP and web tabs, and the shortcut never reaches
  an RDP desktop. Session logs are not masked.
- The rules are patterns: they miss what they do not describe (user names, paths, a password typed
  where no prompt precedes it). Read the preview before you paste.

## Quick file server

- **Links stay inside the shared folder.** A symbolic link or a junction placed inside the shared
  folder led outside it. HTTP now answers 403 and TFTP "File not found" for a path through a link,
  and the directory listing leaves links out. OneDrive placeholders and deduplicated files are
  still served.
- **Several downloads at once.** HTTP requests were served one at a time, so one slow download
  held every other request. Up to eight are served at once; the others wait in the queue, and none
  is rejected.
- Troubleshooting entry 33 says that HTTP without elevation is localhost-only, and gives the
  `netsh http add urlacl` command that opens it to the network.

## Fixes

- **Firewall tester**: a probe report that arrived after the run had ended no longer overwrites
  the final counters, which could show 1 of 2 after a finished run.
