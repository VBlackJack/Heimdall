# Reused RDP controls, keyboard after a tab close, a safer self-update relaunch

This is a fix release. RDP sessions that carried a password now reuse their control instead of
leaking handles, the keyboard works again right after closing an RDP tab, and the self-update no
longer risks leaving you with neither the update nor the application.

## Fixes

- **Closing an RDP session that carried a password no longer leaks handles.** Each new RDP control
  that connects keeps about 66 system handles for the life of the application, so Heimdall reuses
  closed controls. Controls of sessions that carried a password were always discarded instead,
  because their password was wiped while the control was still disconnecting. A closed control now
  waits, hidden, for its disconnection to finish (10 seconds at most), then has its password wiped
  and is reused. The password wipe still fails closed: a control whose password cannot be wiped is
  never reused. Reconnecting after a close asks for the password again.
- **Shortcuts work right after closing an RDP tab.** When the RDP session had the keyboard, closing
  its tab left the keyboard in the closed, hidden control: shortcuts such as Ctrl+N did nothing until
  you clicked the window. The main window now gets the keyboard back.
- **No more warning on every RDP tab close.** Closing a tab logged a `Disconnect failed` warning for
  a second disconnection request the control always refuses. That request is now sent only when no
  disconnection was requested before.
- **The self-update relaunch waits on Heimdall itself.** The update script waited on Heimdall's
  process number. If Heimdall exited before the script got there, Windows could give that number to
  another program: the script then waited two minutes, refused the install and did not restart
  Heimdall. It now also checks the process start time, so another program with the same number is
  recognized and ignored.

## Known limits

- An RDP session abandoned by the connection timeout (45 seconds by default) still waits 10 seconds
  and its control is then discarded, not reused.

## Verified

- Every change was merged with the solution building with no warning, a clean code format check
  and green CI.
- Seen on screen with a test data folder, against a Windows Server 2022 test machine: a logged-in
  session closed, its control reused by the next connection, which asked for the password again; a
  toolbar disconnection reused the same way; after closing a tab that had the keyboard, the main
  window in front and Ctrl+N opening the new session dialog; no disconnection warning in the log.
- Not seen on screen: a real update from an installed build. The relaunch change is covered by
  automated tests, including a test that runs the script against a process with a reused number.
