### Changed

**A session no longer inherits the last one's state**

- **A profile with no RD Gateway no longer travels through the previous profile's.** The
  ActiveX control is recycled between sessions, and settings were written only when a profile
  named one, so a gateway-less session went through the last gateway and presented its
  credentials to it, with no log line saying so.
- **A profile with no username no longer connects as the previous user.** The new profile's
  password was being submitted against the old profile's account.
- **USB redirection, monitor selection and the residual password** follow the same correction:
  what a profile leaves blank is now written rather than skipped.
- **A control whose password could not be cleared no longer returns to the pool.**

**Importing a .rdp file now applies what it read**

- **Every setting read from a .rdp file was inert.** Redirections, security level and colour
  depth were mapped, shown in the preview, then discarded at connect time. The mRemoteNG import
  carried the same defect.
- **A file naming only a gateway no longer routes the session through that host** without an
  explicit usage method, and the preview names the gateway.
- **Replacing a profile no longer drops its SSH bastion, local port and vault link.**
- **A redirection scoped to one drive is no longer widened to all of them** in silence; the
  narrowing is reported as a partial mapping.
- **A port outside the valid range is rejected**, bracketed addresses included.
- **An oversized file is rejected**, as in every other import.

**The embedded view says what is true**

- **Cancelling a connection no longer lets a session that succeeds anyway slip through.**
- **"Edit profile" no longer collapses the overlay for good**, leaving a blank pane with no way
  back.
- **A confirmation dialog that fails is no longer read as a yes.**
- **The certificate check can say it did not happen.** On a profile that routes through an RD
  Gateway the probe could not reach the endpoint, so the outcome was always "could not verify",
  which the gate reads as proceed. It also cost five seconds in front of every connection.
- **The window no longer freezes on connect**: the first credential-autofill scan ran on the UI
  thread.
- **The "prevent sleep" setting is honoured** by the RDP keep-alive tick.
- **The first segment of the progress stepper exists**; it was unreachable.
- **"Copy error" says so when the clipboard is busy** instead of doing nothing.
- **Four English failure messages** were shown verbatim in every locale.

**What a screen reader could not hear**

- **The status line is read out.** A fixed automation name masked its text, so none of the
  disconnect messages reached a screen reader.
- **The health dot, the phase stepper and the reconnect overlay exist in the accessibility
  tree.** Their announcements sat on elements that have no automation peer.
- **Ten live regions declared polite finally raise an event.**
- **The three "Apply to all" buttons in the import dialog announce distinct names.**

**Display**

- **A fullscreen session fits the monitor.** The closest preset was chosen with no fit
  constraint: on a 3440x1440 monitor, 3840x2160 won, putting 400 columns and 720 rows off screen.
- **A fixed resolution of 400 wide opens at 400.** The embedded path enforced a 640 minimum that
  the dialog, the validator and the resolver know nothing about.

**Credentials and process launches**

- **The autofill watcher dies with mstsc.exe.** It kept sweeping the desktop with a plaintext
  password long after the session had ended.
- **A second launch no longer reclaims the first launch's live Windows credential.**
- **Cancelling a connection no longer triggers the deferred artifact cleanup**; it brought the
  deletion forward instead of holding it off.
- **Temporary .rdp files left by a crash are collected.**
- **Nineteen system-tool launches are named by absolute path.** mstsc.exe, and also schtasks,
  arp, nslookup, route, netsh, tpmtool, rundll32, explorer, and above all the update relauncher
  and one elevated launch, which were named bare: the CreateProcess search order puts the current
  directory ahead of System32.

**Certificates**

- **An already-approved thumbprint is found again.** The store deduplicated case-insensitively
  and compared case-sensitively, so the same certificate was asked about every time.
- **A server that refuses the TLS negotiation is no longer described as a server with no
  certificate**, which read as benign.
- **The RDP trust prompt goes through the coordinator** that queues these questions.

**Typography**

- **One typography rule, applied everywhere, with a guard that can fail.** The translation
  catalogue and the sources carried 1139 characters that are only the typographic version of an
  ASCII one. The existing guard explicitly permitted them, so no CI step could ever go red on
  them. Accents, arrows and emoji stay.

**Documentation**

- **Six claims the code contradicted** were corrected in both languages: two measurement
  harnesses presented as shipping with the repository when they do not, two tabs named
  differently from the product, a "TCP-only mode" the client cannot offer, the scope of the
  certificate gate, and a race described as harmless.

### Why

This release is the result of an audit of the RDP surface: sixty-one findings, each read a
second time by an adversarial pass whose job was to refute it before a line was written. Eight
did not survive that reading and are not here.

Two defects dominated, and they are the same family: something was written only when the profile
named it, so what a profile left blank was inherited from the previous session; and an imported
profile kept the flag that says "follow the global defaults", so everything the file said was
read, displayed, and then ignored.

Four findings stay open on purpose, because each needs a decision rather than a fix: the
certificate gate exists only on the embedded path, a certificate trust decision cannot be revoked
from the application, the long connect budget protects the autofill retry at the cost of failing
fast, and a configurable-shortcut path is wired to nothing. They are documented with their
measured options.

### Upgrade note

Nothing to do. One thing is worth knowing: a profile already imported from a .rdp file or from
mRemoteNG was following the global defaults without saying so. Profiles imported after this
version apply what their file contained; profiles already in place do not change behaviour until
they are imported again.
