## Francais

### Changements

**La migration ajoutee par la version precedente est retiree**

- **v2026.090402 renommait les profils enregistres sous un identifiant reserve et deplacait leurs
  certificats approuves. Ce n'etait pas sur.** Une approbation rangee sous un tel identifiant a
  deux proprietaires possibles - une destination tapee qui l'a obtenue avant que le profil soit
  importe, ou le profil - et rien sur le disque ne dit lequel. La deplacer vers le profil est un
  pari, et une fois sur deux c'est un transfert de confiance vers une autre machine.
- Elle ecrivait aussi deux fichiers sans transaction entre eux : une interruption entre les deux
  laissait l'approbation orpheline sous l'ancien identifiant.
- **Si vous avez installe la v2026.090402**, vos profils concernes ont deja ete renommes et leurs
  approbations deplacees. Cette version n'annule pas cela - rien ne conserve la correspondance - et
  ne renommera plus rien.

**Une tache planifiee ne se connecte plus a la mauvaise machine**

- **Une tache dont le profil n'existe plus se rabattait sur le PREMIER profil portant le meme nom
  affiche**, et ouvrait une session dessus sans surveillance. Les noms affiches ne sont pas
  uniques : deux profils s'appellent couramment "Production".
- La tache est desormais resolue par son identifiant, et par son nom uniquement lorsqu'un seul
  profil le porte. Une tache dont le profil a ete supprime puis recree continue donc de
  fonctionner ; une tache ambigue ne se connecte a rien plutot qu'a la mauvaise machine.

### Notes

- **Ce qui reste ouvert.** Un profil enregistre portant un identifiant de l'espace de noms des
  connexions rapides partage toujours sa cle de confiance avec une destination tapee. Depuis la
  v2026.090401 un import ne peut plus creer un tel profil ; ceux importes avant restent concernes.
  Trois corrections successives ont echoue et la quatrieme s'est revelee fausse a la conception.
  Le probleme est documente en interne avec l'analyse complete.

## English

### Changes

**The migration added by the previous version is withdrawn**

- **v2026.090402 renamed saved profiles holding a reserved identifier and moved their approved
  certificates. That was not safe.** An approval filed under such an identifier has two possible
  owners - a typed destination that earned it before the profile was imported, or the profile - and
  nothing on disk records which. Moving it to the profile is a guess, and half the time it is a
  transfer of trust to a different machine.
- It also wrote two files with no transaction between them: an interruption between the two left
  the approval orphaned under the old identifier.
- **If you installed v2026.090402**, the profiles it touched are already renamed and their
  approvals already moved. This version does not undo that - nothing records the mapping - and will
  not rename anything again.

**A scheduled task no longer connects to the wrong machine**

- **A task whose profile no longer exists fell back to the FIRST profile with the same display
  name** and opened a session on it, unattended. Display names are not unique: two profiles are
  routinely both called "Production".
- A task is now resolved by its identifier, and by its name only when exactly one profile carries
  it. A task whose profile was deleted and re-created therefore keeps working; an ambiguous task
  connects to nothing rather than to the wrong machine.

### Notes

- **What remains open.** A saved profile holding an identifier from the quick-connect namespace
  still shares its trust key with a typed destination. Since v2026.090401 an import can no longer
  create such a profile; those imported before it remain affected. Three successive fixes failed
  and a fourth proved wrong at the design stage. The problem is documented internally with the full
  analysis.
