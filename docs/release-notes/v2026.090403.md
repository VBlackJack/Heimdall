### Changes

**The migration added by the previous version is withdrawn**

- **v2026.090402 renamed saved profiles holding a reserved identifier and moved their approved
  certificates. That was not safe.** An approval filed under such an identifier has two possible
  owners - a typed destination that earned it before the profile was imported, or the profile - and
  nothing on disk records which. Moving it to the profile is a guess, and half the time it is a
  transfer of trust to a different machine.
- It also wrote two files with no transaction between them: an interruption between the two left
  the approval orphaned under the old identifier.
- **If you installed v2026.090402**, the profiles it touched are already renamed and their
  approvals already moved. This version does not undo that - nothing records the mapping - and will
  not rename anything again.

**A scheduled task no longer connects to the wrong machine**

- **A task whose profile no longer exists fell back to the FIRST profile with the same display
  name** and opened a session on it, unattended. Display names are not unique: two profiles are
  routinely both called "Production".
- A task is now resolved by its identifier, and by its name only when exactly one profile carries
  it. A task whose profile was deleted and re-created therefore keeps working; an ambiguous task
  connects to nothing rather than to the wrong machine.

### Notes

- **What remains open.** A saved profile holding an identifier from the quick-connect namespace
  still shares its certificate trust key with a destination typed into the palette. Since
  v2026.090401 an import can no longer create such a profile; those imported before it remain
  affected. Three successive fixes failed and a fourth proved wrong at the design stage. The
  problem is documented internally with the full analysis.
