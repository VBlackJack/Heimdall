### Changes

**The .rdp import reads the keys the Remote Desktop client itself writes**

- **A file saved by the Remote Desktop client lost its drive redirection on import.** The
  client saves drive redirection as `redirectdrives:i:1` and never writes the newer
  `drivestoredirect` key; the import read only the newer key, so every client-saved file, and
  every file Heimdall's own generator had written since the previous release, came in with
  drive redirection off while the preview counted the key as "unknown". The logon domain had
  the same fate: `domain:s:` was never read, so a `DOMAIN\user` profile exported with its
  domain in the separate key lost it on the way back in.
- The import now reads `redirectdrives`, `domain`, `redirectcomports`, `audiocapturemode`,
  `administrative session`, `compression`, `bitmapcachepersistenable`,
  `autoreconnection enabled`, `usbdevicestoredirect`, `camerastoredirect` and
  `dynamic resolution`, and maps each onto the profile field it belongs to. When a file carries
  both drive keys the newer one wins, which is the precedence the client applies. A test reads
  a generated file back through the import and checks every field the format can carry.
- The generator writes its seven performance keys for every profile, a zero mask included. A
  file silent on them left the client to whatever its own `Default.rdp` remembered from the last
  session someone ran by hand.

**A session torn down while it was connecting no longer keeps the machine awake**

- **Closing a tab at the wrong instant left Heimdall holding the machine awake until it
  exited.** The connected handler flushes the layout after a connect, and that flush pumps
  messages; a tab closed inside the pump disposed the view, which released its sleep-prevention
  count, and the handler then acquired that count again on the disposed view with nothing left
  to release it. Each such close added one to the count for the life of the process.
- The handler re-checks disposal after the flush and leaves, as the connect path has done
  since the pre-connect flushes were guarded.

**Smaller corrections**

- A reconnect keeps the RDP mode the user forced on the tab. A session opened as "force
  embedded" over a profile whose mode is External reconnected from the profile, so the
  overlay's Reconnect button launched the external client and closed the embedded tab under a
  title that still carried the forced suffix.
- The RD Gateway field is trimmed and validated when the profile is saved, by the address rule
  the .rdp generator and the embedded host apply before they route a session through it. A
  malformed host used to be saved as typed and refused at connect time by the attestation
  sentence; the error now names the box, on the Network tab, and clears as you type.
- The credential autofill recognises the confirmation button and the password field in every
  locale it recognises the dialog in (English, French, German, Spanish, Italian, Portuguese,
  Dutch, Polish). The dialog title was recognised in eight locales while the button label was
  known in two; on the other six the fill fell through to the first enabled button.
- The autofill watcher resolves each process name once for its lifetime instead of opening one
  process handle per visible window on every half-second scan.
- The credential autofill timeout and the resize-enable delay have named defaults; the four
  surfaces that restated them as literals read those now. The anti-idle tick reaches the
  rendering surface through the same helper the Send Keys menu uses.

### Notes

- **What was not measured.** The drive-key precedence is the one measured in the client's
  editor for the previous release; the import follows it. An empty `drivestoredirect` beside
  a `redirectdrives` switch defers to the switch, which was not measured against the client and
  is stated as such in the code.
- **Left open on purpose.** The colour depth setting still accepts 8 bits and rewrites it to
  16 at connect time; whether to lower the bound or document it is a decision, not a fix. The
  external launch still performs no certificate check of its own, and the connect watchdog's
  longer credential budget is still armed when the autofill watcher starts rather than when it
  sees a prompt; both are unchanged from the previous audit.
- See FEATURES, "Unified RDP import", for the list of keys the import reads.
