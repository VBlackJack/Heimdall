### Changes

**Tunnels: three parked audit findings, reproduced and fixed**

The SSH audit of 2026-09-06 had parked four findings as plausible but unproven. Each was
reproduced against the real code paths first; three are fixed here, the fourth was refuted
by measurement and left alone.

- **Closing a pane no longer closes a tunnel another pane still uses.** When a WinRM
  terminal process exited at the moment its pane was closed, both the exit handler and the
  close read the pane's tunnel port, released it, and only then cleared the state: one
  acquisition was released twice, and a tunnel shared with a third session was torn down
  under it. The port is now handed out once, to whichever path asks first.
- **An external launch is no longer served by an embedded session's tunnel.** An external
  Remote Desktop launch asks for a distinct loopback alias because its saved credential is
  keyed on the tunnel host, and two launches sharing 127.0.0.1 collide on the same entry.
  Tunnel reuse ignored that request and handed back the default-loopback tunnel; it now
  skips such tunnels when the preference is set and opens an aliased one instead.
- **The plink diagnostics drain outlives the connect.** It was tied to the connect's
  cancellation; had that been cancelled after the tunnel was up, plink would have blocked on
  its next diagnostic line and the forwarding would have stopped silently. No path in the
  application cancels it that late today, so this closes a latent fault.
- Not changed: stopping a plink tunnel was suspected to wait the whole drain timeout. It
  takes about 50 milliseconds when measured; the suspicion was wrong.
