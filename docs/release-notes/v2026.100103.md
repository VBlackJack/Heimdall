# Settings show what you changed and what affects security, and every count reads right

A release about the Settings screen: it now opens its Security tab on a summary of the
choices that affect security, shows which settings differ from their default and lets
you put one back, and opens from the keyboard. The last counts written with "(s)" are
gone.

## A security overview on the Security tab

The Security tab now opens on a Security overview card, with one line for each choice
of the Settings screen that affects security and its current state: NLA and strict
server authentication, TFTP sharing, session transcripts, the PowerShell execution
policy, the master password, auto-lock, disconnect on lock, Credential Guard, Windows
Hello, update checks and the known_hosts import.

A choice documented as insecure carries a warning icon, says why, and has a Go to
setting link that takes you to it. The card follows your edits as you make them and
marks a line Unsaved until you save. The line counting what needs attention is
announced to screen readers when it changes.

## See which settings you changed, and put one back

- **A changed setting says so.** A setting whose value differs from its factory
  default shows a "Modified" badge after its field, which a screen reader reads with
  the default value, and a Reset button beside it.
- **Reset puts back that one setting.** The default comes back as a pending edit:
  nothing is written until you save, and Undo changes takes it back. Language, theme
  and accent can be put back this way too, which Reset defaults does not do. The
  credential provider unlock secret, the external tools list and the settings saved
  immediately carry no badge.
- **Find modified settings**, beside the search box, counts the settings that differ
  from their default and walks through them with Enter.
- **Changing a setting back clears the pending state.** Ticking a box and unticking it
  again left Save enabled and the unsaved dot on the Settings tab, over a panel
  identical to the saved one. The panel now counts as changed only while it differs
  from what is saved.

## Ctrl+, opens Settings

No shortcut reached the Settings tab. Ctrl+, now opens it from anywhere in the window,
the same way a click on its tab does, and the F1 help lists it.

## A settings import names what it changes

Before loading a settings file, Heimdall listed the settings that would change by
their internal names, such as "TerminalFontSize", in English whatever the language,
and without their values. Each line now names the setting by where it lives on the
Settings screen, with its current and new value: "Terminal > Terminal Appearance >
Font size" going from 14 to 18, or On to Off for a checkbox. With one change, it says
"1 setting will change" rather than "1 settings".

## Every count reads "1 certificate", not "1 certificate(s)"

The previous release left some messages for later; they are now done.

- **No "(s)" left in the interface.** The last texts that wrote a count as "1
  certificate(s)" now take the singular or the plural their number calls for, in each
  language. This covers the SecNumCloud audit summaries and evidence, the tool tabs
  (WiFi, routes, interfaces, open ports, DNS batch, TCP ping, regex, notes,
  certificates, CVE lookup, default credentials, the command library import), the
  import summaries and dialogs, the SFTP partial results and the session restore
  warning.
- **A sentence with several counts words each one on its own.** "1 imported, 0
  replaced, 2 skipped" agrees each word with its own number in French and Spanish,
  where one shared "(s)" used to cover them all.
- **The session tree counts zero the French way.** The filter result under the
  session search, the hint shown while dragging sessions and the status after moving
  them into a folder follow each language's rule, as the status bar does.
- **The WiFi tab no longer shows a template before the first scan.** Its empty panel
  read "{0} network(s) at {1}"; it now invites you to click Scan.
- **A bulk password edit that skipped every profile says only that.** When no selected
  WinRM profile had a username, the status no longer reads "Password updated on 0
  server(s)" before naming what was skipped.
