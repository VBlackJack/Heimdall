# Session tabs that show their state, and a properties panel you can act from

A release from a UX pass over the session tab strip and the properties panel. A tab now shows
when its session needs a look, the strip can be driven from the keyboard like a browser's, and
the properties panel connects, edits and names what it shows. It also keeps the mouse pointer
visible after an embedded view closes, a fix contributed by @Anghios.

## Session tabs

- **A tab shows its session's state.** A tab that is connecting carries a pulsing dot, one whose
  session dropped carries a ring, and one that failed carries a warning sign. A connected tab
  carries nothing, so with thirty tabs open the six that dropped stand out. A screen reader hears
  the state after the tab's name.
- **The tooltip tells two tabs apart:** the full title, the address and protocol, the user, the
  folder, and the state or the failure reason when there is one.
- **Keyboard:** Ctrl+PgDn and Ctrl+PgUp go to the next and previous tab, also from a terminal.
  Ctrl+Shift+PgDn and Ctrl+Shift+PgUp move the tab. Ctrl+1 to Ctrl+8 go to that tab, Ctrl+9 to
  the last one.
- **Reopen what you closed with Ctrl+Shift+R.** A "Close others" or "Close all tabs" comes back
  whole, not one tab at a time; the menu says how many tabs it will reopen.
- **"Close all tabs" is in the tab menu,** and its confirmation counts the open and the connected
  tabs.
- **The menu item that read "Disconnect" now reads "Close tab",** which is what it always did.
- **"Close others" and "Close to the right" leave a collapsed folder alone.**
- **Dragging a tab near either end of the strip scrolls it,** so a tab can be dropped beside one
  that was out of view. A tab let go over the session tree or the toolbar no longer pops out into
  a window of its own; dropping it outside the window, or over the session area, still does.
- **The close button names the tab it closes,** and a folder chip that cannot fold its tabs,
  because they are the only ones open, says why.

## Properties panel

- **Connect and Edit buttons** under the session's name. The panel used to show a session with
  nothing to do with it while a tab was open.
- **Project and Origin** are shown, after the folder.
- **A value's tooltip shows the value in full,** then how to copy it, so a long host name cut at
  the sidebar's edge can be read.
- **A screen reader hears each value with its field,** for example "Username: admin".
- **Ctrl+Shift+B shows the panel** when the Tools tab is up or the sidebar is hidden, instead of
  switching it off out of sight. The close button's tooltip says how to bring it back.
- **A selected tool** is shown as a tool, not as if nothing were selected.
- **The panel's height is kept** after a drag, after a resize with the arrow keys, and when the
  window changes size.

## Embedded views

- **The mouse pointer stays visible after an embedded view closes** (issue #577, contributed by
  @Anghios). WebView2 runtimes 152 to 154 hid the pointer while typing and could leave the whole
  window without one once the view closed. Heimdall now asks every embedded view not to hide the
  pointer while typing.
