### Changes

**Exit closes every session before WPF has torn the application down**

- Closing Heimdall with sessions open tore each session down after WPF had already discarded the
  application object, which is what an asynchronous exit handler does at its first pause. The log
  showed it as "UI dispatcher is not available" on every connection and a NullReferenceException on
  the active tab. Sessions are now closed before the exit handler pauses, and the session snapshot
  used for restore-on-launch is captured before the close empties it.
- A second NullReferenceException inside the Remote Desktop teardown was not located. It ran under
  the same condition and no longer does; if it comes back, the log line now carries the stack
  instead of the message.

**Renaming a gateway reaches every session row**

- A session row resolved its gateway's name once, when it was built. After a rename, rows that had
  not been edited kept the old name in their badge, tooltip, detail pane line, the name a screen
  reader announces, and the {Gateway} token of external tools. Every row now re-resolves when the
  configuration changes.
- The route shown on a session tab, in the Tunnels panel and on a certificate question keeps the
  name the connection was dialled through. That is on purpose: it records what happened.

**The scheduled-task log says which of three refusals it made**

- A scheduled task can match no profile in three ways: it records an identifier no profile carries;
  it records no identifier and no profile carries its name; or it records no identifier and several
  profiles do. The log reported all three as a deleted profile. It now names the case.

### Notes

- Nothing in this version changes what a scheduled task connects to, only the sentence the log
  writes when it connects nothing. See the Troubleshooting guide, section 50.
- The "Route via" selectors inside the network tools still list the gateways as they were when the
  tool tab was opened. Reopen the tab after editing a gateway.
