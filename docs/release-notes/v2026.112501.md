# Choose which tools appear, and add your own as recipes

This release sorts the built-in tools into packs you can turn on or off, and lets you add tools of
your own as recipes: small text files that run a program already on your computer with the
arguments they declare. Recipes are off by default.

## What you will see

### Tool packs

- **The built-in tools are sorted into packs.** The Command Library and Notes are always there.
  Four packs of built-in tools can be turned on or off: Essentials (offline converters, generators and checkers),
  Network diagnostics, Administration, and Audit and reconnaissance (port scanner, banner grabber,
  SNMP walker and the other tools that probe a target).
- **Where the switches are:** Settings > Advanced > Tools & integrations > Tool packs. Each switch
  shows what the pack holds; the Audit and reconnaissance switch reminds you to use those tools
  only where you are authorized. Changes apply when you save.
- **A fresh install starts with Audit and reconnaissance and Recipes off.** An existing install
  keeps every pack on, except Recipes, which starts off once.
- **A tool in a pack that is off is hidden everywhere** (Tools tab, sidebar, command palette, tool
  picker) and cannot be opened. Your favorites and saved tool entries are kept and come back when
  you turn the pack on again; meanwhile a saved entry is shown dimmed, with the reason.
- **An administrator can forbid a pack with a machine policy.** Its switch then shows off and
  cannot be changed. This is a convenience for administrators, not a security boundary.

### Recipes

- **A recipe is one text file** (`*.heimdall-recipe.json`) that describes a tool: a program already
  on the computer, the fields to fill in, the arguments to give it and how to show its output. It
  carries no script and no program of its own, and it never runs through a shell. The format and a
  complete example are in the tools documentation.
- **Turn the Recipes pack on, then import:** Settings > Advanced > Tools & integrations > Recipes,
  Import a recipe... Before anything is kept, a preview shows the program that will run, every
  argument exactly as written, the fields, the translations and every other setting of the file.
  Replacing a recipe shows what changed.
- **An imported recipe appears in the Tools tab under Recipes**, marked "Unverified recipe by" and
  the name the file gives. It reads nothing from a session except the host and the port of the
  selected one.
- **Fields can have a help text, a minimum and a maximum.** A value outside the range is refused
  under its field, with the range in the message.
- **Tables are shown as a grid.** A recipe can show its output as CSV (comma, semicolon or tab) or
  JSON. Copying a table neutralizes a cell that a spreadsheet would read as a formula.
- **A recipe can be translated.** The open tool shows the name, description, field labels and help
  texts in the language of the interface when the file provides it.
- **When a recipe will not load, the list says why**: the file changed, is missing, cannot be read,
  or is not accepted by this version.

## Security

- **What a recipe may run is checked before every run.** The program must be found under Windows,
  Program Files, or a folder you add yourself; under Windows and Program Files, the file and every
  folder above it must not be writable or owned by an ordinary account. Shells and script
  interpreters are refused by name.
- **A folder you add cannot open more than itself.** A folder that leads to the root of a drive or
  to a network location, a mapped drive included, is refused when you add it.
- **Values are checked before they reach the program**: no character that looks like a dash or a
  quote but is not one, no value that would be read as an option where it starts an argument, no
  number written in a form a program could read differently.
- **A run is placed in a job**, with a time limit and a cap on the output kept.
- **Recipes are not signed and not reviewed by the project.** The rules above do not make a recipe
  safe: a legitimate program can do harm with its own arguments. The security documentation says
  what is protected and what is not. Import only recipes you have read and trust.

## Packaging

- **The packages no longer carry the source of the Notes editor or its development
  dependencies.** The build now refuses to package them, and an upgrade with the installer removes
  them if an earlier installation has them.

## Fixes

- **Switching the interface language now also rewords the open recipe tools**, and no longer
  reports a failure once the Recipes card of the settings had been shown.
- **Message dialogs carry a window title**, so screen readers and window lists name them.

## Upgrade notes

- **Tables copied from external tools follow the recipe rule.** A cell that starts with `=`, `+`,
  `-` or `@` is copied with a leading apostrophe, so a negative number or a time offset pastes into
  a spreadsheet as text. Plain text output is copied as is.

## Verified

- Every change was merged with the solution building with no warning, a clean code format check
  and green CI. The recipe file format is pinned by a suite of 37 accepted and 71 refused sample
  files that must keep giving the same result.
- Tried on screen with a test data folder: importing and replacing recipes and reading their
  preview; running a recipe and stopping it; a value outside its range refused; a semicolon CSV
  output read in the ANSI code page with accented letters; a copied cell starting with "=" pasted as
  text; turning the Recipes pack off during a run, which cancels it; a recipe tool in French;
  adding a folder under Windows, which shows a notice.
- Measured on Windows 11: which encoding common console tools write when their output is
  redirected (most use the OEM code page; certutil, sort and findstr use the ANSI code page; sfc and
  wsl write UTF-16; netsh writes UTF-8), which is why recipes can choose among those.
