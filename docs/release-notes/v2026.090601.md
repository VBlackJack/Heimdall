### Changes

**The SSH layer, audited: 34 findings fixed**

An audit of the SSH layer, from the SSH.NET handshake to the embedded terminal, found 43
issues; this release fixes 34 of them, two of which are security fixes. Every fix ships with a
test that failed on the previous release.

**Host key trust**

- **Replacing a host key no longer exports the rejected key.** Accepting a changed key through
  the Plink path, or choosing "Replace" in the import conflict dialog, stored the new fingerprint
  over the public key of the entry being replaced. The known_hosts export then wrote that old key
  back into `~/.ssh/known_hosts` under the host the user had just re-trusted. The old key material
  is now dropped, and a conflict carries the imported key so "Replace" stores the key it refers to.
- **A changed host key no longer answers Enter with "Trust this session".** On a mismatch the
  default and focused button is Reject, as OpenSSH refuses outright; Accept and Trust-once take an
  explicit click. The FTPS certificate prompt follows the same rule.
- **Importing a known_hosts file detects conflicts against hashed entries.** A host already
  trusted through a hashed `|1|` line showed as New when a plain line for the same host arrived,
  and the plain line was written next to it and silently took over. The importer now asks the trust
  store, which matches hashed entries, before classifying a line. Resolving a mismatch against a
  hashed entry also removes that entry instead of leaving the old fingerprint behind it.
- **The known_hosts export is written without a byte order mark**, which OpenSSH does not strip
  and which made the first line fail to match its host on every `ssh` call. A multi-host line
  (`web1,10.0.0.5 ...`) is kept verbatim and the managed line appended, instead of dropping the
  second alias.

**X11, generated keys, Plink**

- **The managed VcXsrv keeps its host access control.** It was started with `-ac`, which let any
  host that could reach TCP 6000 on the workstation read the forwarded windows and the clipboard.
  The only client Heimdall points at the display is the local one.
- **Generated key files are readable by OpenSSH and PuTTYgen.** The key generator wrote both
  files with a byte order mark in front of the PEM header and the key type token, and left the
  private key with the folder's inherited permissions. Files are now UTF-8 without BOM with LF
  endings, and the private key is created with an owner-only ACL.
- **The Plink fallback refuses a profile it cannot serve.** When the built-in client's sign-in to
  a gateway was refused and Pageant was running, the fallback opened a plain local forward and
  reported success even for a profile that needed a SOCKS proxy or a reverse forward, which then
  did not exist. It now refuses with a message naming the missing forward.
- The plink host key probe reads `ecdsa-sha2-nistp*` and security-key types instead of storing
  `ssh-unknown`; the SSH key audit tool names the file it could not read instead of doing nothing.

**Connecting and cancelling**

- **Cancelling a connect stuck in the handshake now stops it.** A cancel during the key exchange
  did nothing until the connect timeout, then reported "Connection timed out" as an error. The
  handshake now observes the cancellation, and a cancelled attempt is reported as cancelled.
- **A wrong key passphrase is reported as such.** With a password also stored, a key whose
  passphrase was refused was dropped silently and the next refusal blamed the key the server never
  saw. The password fallback now applies only to a passphrase guessed from the legacy password
  mapping.
- A relative or missing key path fails before dialling with the same message on both transports;
  a reset during the banner read is classified as a network failure instead of a raw exception.

**Tunnels**

- **Cancelling during the establishment delay no longer leaks the tunnel.** The tunnel was
  already registered but nothing owned it, so it stayed open until the application closed.
- The Tunnels panel no longer throws when a tunnel is released while it refreshes; the health
  monitor stops polling when the session's client is gone and restarts on reconnect when the
  panel is open; the shell read loop is owned by the session, not by the connect token.

**Embedded terminal**

- **Pasting goes through xterm's paste path.** A confirmed paste was re-injected as raw
  keystrokes, so bracketed paste never applied and a Windows `\r\n` submitted an extra empty line.
  Shift+Insert now goes through the same paste guard as Ctrl+V.
- **The TMOUT reset only fires into an idle SSH shell.** It sent a bare Enter every interval
  regardless of what was half-typed, into local and WinRM terminals too, and recorded it into macro
  recordings. It now waits for the shell to be idle, applies to SSH sessions only, and is never
  recorded.
- **The terminal opens at its real size.** The size xterm reported before the session was
  attached was dropped, leaving the PTY at 80x24 until a window resize.
- When X11 forwarding is requested and no X server is available, the session says so in its
  status text and launches without forwarding.

**Import and translation**

- `HostName %h.domain` in an ssh_config expands `%h` to the alias; other tokens produce a
  diagnostic and skip the entry. A directive repeated inside one `Host` block keeps its first
  value, as OpenSSH does.
- Tunnel failures composed in the SSH layer, session disconnect details, import diagnostics and
  the key audit file filter are translated instead of shown in English.
