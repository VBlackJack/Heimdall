The largest release since the Remote Desktop handle leak was closed. It ends a loop that Windows
cannot end, gives you a way out of a file save that never returns, and makes a failed update say so
instead of pretending it worked.

### Read this before you update

The script that performs an update comes from the version you already have, not from the one being
installed. Two of the fixes below are in the *new* relaunch script, so they cannot help this
particular update. They protect every one after it.

Concretely: if you trigger the update and Heimdall closes and nothing comes back, no installer, no
error, then you are on a machine where the old script died before it could launch anything. Run the
downloaded installer yourself, once. From then on the problem is gone for good.

### Remote Desktop no longer asks about the same pool forever

Windows stores exactly one Remote Desktop server thumbprint per host name. Behind one name there is
often more than one machine, a pool of domain controllers for instance, each with its own
self-signed certificate. Every connection can land on a different member, so the stored thumbprint
disagrees, the warning comes back, and accepting it overwrites the previous one. The next
connection starts over. This is not a Heimdall defect: native mstsc does the same thing, for the
same reason.

Heimdall now keeps a set of approved thumbprints per profile, so each machine in a pool is approved
once and the profile then stays quiet until a machine is rebuilt.

You will see the question only where nothing was checking before, which means profiles with Network
Level Authentication switched off. With NLA on, Windows performs its own check and Heimdall adds
nothing, no prompt and no delay.

The question tells you how many certificates this profile already trusts. That matters: the second
one on a pool is normal, and it should not read like the same alarm a second time. Answering "Just
this once" is never written to disk. Declining stops the connection and says why.

Anything that could not be verified connects exactly as before. An unreachable machine, one that
offers no certificate at all, a check that fails for any reason: all proceed untouched. A
verification step must not become a new way for something to fail that used to work.

### A stuck file save no longer traps you

Editing a remote file over SFTP could leave you with nothing to do. If the save wedged, the editor,
the panel and the tab all refused to close, and the close button did nothing.

Worse, in the common case the button did not merely refuse, it lied. During a save the file still
counted as modified, so you were asked whether to close and discard your changes, you answered yes,
and the answer was silently thrown away.

The editor now offers to cut the SFTP connection, which is the only action that reaches a write
already handed to the library. The answer that destroys nothing is on both Enter and Escape.
Pressing the button a second time tells you what already happened rather than asking again about
something that is already done.

Working directories left behind by earlier sessions are cleaned up when the application starts,
including ones a previous version had no way to remove.

### An update that does not install now says so

The relaunch script used to report success no matter what. The installer exit code was never read,
and the one branch that could have reported a failure was unreachable code that looked correct. The
transcript is now written where you can find it.

There was a second and worse case: on some machines no update could install at all, silently. The
script asked Windows for a signature verdict without guarding the call, and where the PowerShell
security module will not load, that command does not exist. The script stopped there, before the
installer was ever started. Obtaining the verdict is now allowed to fail. An invalid signature
still refuses the installer, and the checksum verified straight afterwards is unchanged.

### Smaller things

SFTP now asks for a password when a connection is refused for want of a usable credential, retries
once, and says the same thing SSH says in that situation.

A dropped VNC session no longer shows "Connected" in the status bar while the panel reports that it
disconnected.

The Base64 tool no longer risks running a conversion twice on a single activation.

### For screen reader users

Selecting several sessions at once used to be reported half-complete: a screen reader could be told
about one of two selected servers. Server rows also announced an internal class name instead of the
server name and its state. Both are fixed. Neither was visible except to a real accessibility
client, which is how they lasted.

### What to check first after updating

In this order, because that is roughly how visible a problem would be:

1. Open a Remote Desktop profile that has NLA switched off. The certificate question should appear
   before anything tries to connect.
2. Decline it. The tab should stop and tell you why, and no session should open.
3. Reopen and approve. The session should open normally.
4. Reopen a third time. There should be no question at all.
5. Open a profile with NLA on. There should be no question and no added delay.
6. Edit a file over SFTP and save it. Normal saves should be unchanged.
