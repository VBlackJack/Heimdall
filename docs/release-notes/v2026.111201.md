# A Tools tab group, the SSH agent key of a session, and terminals that start at the right width

A release of fixes and a few additions. Several items come from the same user report as the two
previous releases (GitHub discussion 500, a migration from mRemoteNG): the Tools group, the choice
of an agent key, and the terminal width. The others come from a second pass of code review, which
looked again at places where Heimdall could lose work, skip a safeguard or send a secret where a
file decides.

## What you will see

### Tab strip

- **Tool tabs are gathered in a "Tools" group.** With tab grouping on, the tool tabs that are not
  pinned form one group, like the tabs of a folder. It has its own menu wording and its own
  accessible names, so it is never mistaken for a folder named "Tools". In the "folders on their own
  row" layout the group has its header and folds like the others.

### SSH

- **A session can name the one agent key it offers.** The session dialog has an "Agent key" list in
  the SSH/SFTP credentials card: "Any key (default)", or one of the keys loaded in Pageant or the
  Windows OpenSSH agent. With several keys in an agent, a server that allows few attempts no longer
  refuses the session before the right key is tried. It applies to the SSH terminal, to SFTP
  sessions and to the SFTP side panel. A stored password, a key file and keyboard-interactive
  authentication behave as before.
- **A chosen key that is not loaded is refused with a clear message** naming its fingerprint. There
  is no fallback to the other keys and no prompt before the refusal.
- **The choice stays on this machine.** It is not written to shared session files, an import clears
  it and the settings export leaves it out. With agent forwarding on, the dialog warns that the
  remote host can still use every key of the agent.
- **Sessions that go through Plink** (agent forwarding with Pageant, or a retry after the embedded
  client failed to authenticate) pass the chosen key to Plink. They are refused, with one message
  per cause, when the key is not in Pageant, is of a type Plink cannot read (hardware "sk" keys for
  example), when a key file is also set on the session, or when Plink is not the bundled build.
  The choice is not applied to gateway hops and tunnels, which still offer every agent key.
- **No more blank terminal on equipment that prints its prompt once.** Output sent by the server
  before the terminal was ready, such as a banner or a first prompt, was dropped; the terminal then
  stayed blank until you pressed Enter. That output is now kept and shown. This was checked on a
  scripted stream, not on real network equipment.
- **A device that answers and closes at once is shown as disconnected,** with its message ("max
  sessions reached" for example), instead of a tab that looked connected.
- **Terminals that go through Plink start at the real width of the pane.** Plink cannot change its
  terminal size after it starts. It was launched at 80 columns, or at a width measured while the
  terminal was still hidden, which was not the width of the pane, so the remote wrapped lines at the
  wrong column: the command line overwrote the prompt and pasted text stayed highlighted. The
  terminal now gets the real size of its pane before the session starts, and an SSH tab with the
  SFTP side panel opens already split, the panel showing as loading until SFTP connects. This was
  hand tested against an OpenSSH server at
  100% display scaling; other scalings were not tried.
- **A badge in the session header** appears when such a session cannot follow a new width, for
  example after you maximise the window. The full sentence, with the remedy (reconnect), is in its
  tooltip.
- **The Plink host key check stops before any authentication.** To learn which host key a server
  presents, Heimdall runs Plink once before deciding whether to trust it. On a host already known to
  PuTTY, that run could go on to authenticate through Pageant and open a shell until its timeout. It
  now stops after the server has shown its key.

### Session tree

- **Moving a session up or down no longer scrolls the tree back to the top.** Each move rebuilt the
  whole tree, so the view jumped and several moves in a row were slow on a large inventory. A change
  of order now moves the row in place, and the row is scrolled into view only when it is hidden. A
  move to another folder still rebuilds the tree.

### Credentials and import

- **A session that comes from a file or a scan makes no lookup in an external credential provider
  until you confirm it.** A provider looks a password up under the session's entry name, or its
  display name, and an imported file chooses both, as well as the host. This covers every import
  (JSON, mRemoteNG, MobaXterm, RDCMan, .rdp, PuTTY, OpenSSH config), the network scanner and the
  Citrix cache scanner. Until confirmed, the connection asks for the password as usual. Sessions you
  created yourself, and files without the new field, are unchanged.
- **A "Confirm credential lookup..." command** on a session, a selection or a folder lists, for each
  session, the entry that will be looked up and where the connection goes: protocol, host, port,
  user, gateway chain. Declining is the default, and at most ten sessions are shown at a time. When
  you save the session dialog, it shows a notice with an "Allow lookup" button instead of
  confirming silently.
- **The reason is not hidden.** When you connect such a session by hand, the line saying that the
  saved-password lookup is off stays as the last status instead of being replaced by the result of
  the connection.
- **Renaming such a session no longer freezes the name chosen by the file as its entry name.**
- **KeePass presets use the full program path.** The KeePass 2 (KPScript) and KeePassXC commands
  named a program that a standard install does not put on the PATH. They now start with the quoted
  path under Program Files when the program is there, and with the bare name otherwise.
- **The import preview shows the port the session uses.** A session that was not RDP was listed with
  the RDP port, 3389 by default.

### SFTP

- **A privileged (sudo) save can no longer leave the sudo password in the saved file.** The
  password and the file content went through the same input, and with a wrong password or some
  sudoers setups the password could end up at the top of the written file. The content is now staged
  first and installed with one sudo call whose input carries only the password. Failures are told
  apart: rejected password, password or terminal required, not in sudoers, sudo missing, no
  temporary space. A rejected password is reported clearly from the remote editor too.

### Work that is no longer lost, and safeguards

- **Command library sync never updates a template of a built-in command.** A synced template file
  could still rewrite the command of a built-in action while its title and danger level stayed. Such
  an update is skipped and reported.
- **SSH key files are written without deleting the old ones first.** A failed write (disk full,
  share, power cut) could lose the previous key. Keys are written beside the target and put in
  place once complete, and a failure is shown in the tool.
- **Moving the open note saves it first.** Unsaved edits were written back to the old place and
  stale text was shown. The back and forward history follows a move and a rename.
- **The confirmation of a web session's external program shows control characters.** It also
  refuses a program on a network or device path, a file URI, a quoted value, and a command too long
  to be shown in full.
- **The restore dialog shows the real names** of sessions hidden by a filter and of shared sessions,
  instead of "Unknown server".

## Upgrade notes

- **Imported sessions ask for their password until you confirm the lookup.** If you use an external
  credential provider, run "Confirm credential lookup..." once on the folder or the selection, ten
  sessions at a time. This includes restoring your own export. Sessions imported by an earlier
  version are not affected and keep the lookup by name.
- **An SSH session that drops within the connect-time window (15 seconds by default) with nothing
  typed no longer reconnects by itself.** It shows the disconnected state and the reconnect button.
  Without this rule a device that closes right after connect was redialled without bound.
- **An SSH tab with the SFTP side panel opens already split,** and layout commands (split, swap,
  toggle, merge, detach) are refused for the few seconds the panel is loading, with a status
  message. A merge from a tab that is still connecting is refused too. Bulk connect keeps its
  previous sequence, so a Plink session started that way can still start at a wrong width: the
  badge says so.
- **In the "folders on their own row" tab layout, tool tabs now fold with their group** instead of
  staying visible whatever folder is shown.
- **A session with a chosen agent key is refused in external PuTTY mode and in some Plink cases,**
  with a message naming the cause.
- **The choice of agent key is not exported, not imported and not shared.** Set it again on each
  machine.
- **A web session no longer starts an external program on a network share.** A portable browser
  started from a share is refused too, as for the Citrix SelfService path in the previous release.
