# Missing MobaXterm variables, named and one click away

A small release that follows v2026.110501. When the sessions of a shared source use a MobaXterm
variable that has no value on your computer, Heimdall now reports it once instead of once per
session, and the Settings page names the variable with a button that adds it.

## What you will see

### Shared sessions: the import report

- **One finding per missing variable.** A variable such as `[DAS]` with no value used to give one
  finding per session that uses it, 79 lines for 79 sessions. The report now shows one warning per
  variable and source: "[DAS] has no value in the MobaXterm import variables: 79 sessions loaded
  with the token as written." The count on the source counts variables, not sessions.
- **Copy and Export CSV still list every session.** Copy lists them under the finding; the CSV
  gives one row per session, so a spreadsheet can still filter by folder.
- **A gateway such as `[DAS]@bastion` stays on one line** in the report window; the sentence wraps
  around it.

### Settings: MobaXterm import variables

- **The card names the variables your shared sources need.** "Used by shared sources but not
  defined: DAS (Test004)" lists each variable that an enabled shared source uses and that has no
  row, with the source that uses it.
- **One click adds the row.** The "Add DAS" button adds a row named `DAS` with an empty value and
  puts the cursor in the Value box. Nothing is saved until you save the page.
- **Name and value, explained.** The Name is what the file writes between brackets (`DAS`); the
  Value is your own login (`jdoe`). The guide now shows it with an example.

## Upgrade notes

- **The report holds fewer lines.** A source that showed 79 warnings for one missing variable now
  shows 1. Copy and the CSV keep one line per session, so a script that reads the CSV is unchanged.
- **A row with a name and an empty value counts as defined.** The card no longer lists that
  variable; the row itself asks for a value.
