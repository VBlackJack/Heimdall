This release was written for the person who did not build Heimdall. Everything in it was found by
asking a different question than usual: not "what is broken", but "what stops someone getting out of
a situation, and what fails without saying anything at all".

Seventeen such defects were confirmed. The ones below are the ones you can notice.

### The workspace lock no longer freezes the application permanently

Five wrong master-password attempts disabled the password box, the Unlock button and the Windows
Hello button together, and never re-enabled any of them. The lockout expires by itself after five
minutes, and the message on screen told you to wait for it, but nothing ever re-read that expiry.
The only way out was to kill the process, which discarded every open session.

The lock overlay covers the whole window, so this stopped the entire application. On the startup
gate the lockout is remembered across restarts, so relaunching returned to the same dead dialog.

The countdown now re-checks itself and reopens the gate when it expires, and the remaining time
stays truthful as it counts down.

### Resetting settings no longer deletes your SSH gateways and projects

"Reset Defaults" sits beside Save on every Settings tab, and its confirmation said only that servers
were not affected. Confirming it and then saving emptied every SSH gateway and every project.

What went with them cannot be recovered. A gateway carries a stored password, a key passphrase and a
host fingerprint, and the interface only ever reports whether those exist, never their value. There
is no settings backup. Every server pointing at a deleted gateway was left pointing at nothing.

Gateways and projects are now kept across a reset, which is what the confirmation always implied,
and the confirmation now names what it keeps.

### Forgetting the master password is now stated before you choose it

Turning on the master password described what it protects and not what it costs. It cannot be
recovered or reset: forgetting it means Heimdall will not open and the stored credentials are lost.
The text now says so, before the decision rather than after it.

### Deleting a file you do not own now asks before deleting it as root

If your account was refused, the delete quietly escalated to a recursive removal running as root.
You answered one ordinary confirmation, and the directory went away with everything inside it,
removed by a privileged command you were never told about. The success message did not mention it
either.

You are now asked, once per deletion, in a prompt that names the entry and says a folder goes with
all of its contents. Declining leaves the entry alone and says why.

### Exports and copies that fail now say so

Twenty-five places wrote the failure to a log file and told you nothing. Choosing a filename for an
export and confirming it produced no file and no message. Pressing Copy showed the usual feedback
and left the previous clipboard contents in place, which for the password generator meant pasting
the previous secret. Confirming the clearing of the network cartography knowledge base left you
believing it had happened.

All of them now report the failure where the view already shows its errors. The scan results stay on
screen: the scan succeeded, only the save failed.

### Settings that will not save now say why

Saving can be refused for a reason that raises no badge and no summary, such as the file being
unwritable. Pressing Save then did nothing at all. Worse, leaving the Settings tab with unsaved
changes held you there without a word, so every further attempt to leave repeated the same silent
refusal.

### A connection with no username is refused before it starts

An SSH or SFTP profile saved with an empty username raised a tunnel, showed the host key prompt,
had you accept and trust the server, and only then failed with a raw .NET parameter error. Nothing
about that error suggested the username. The profile is now refused before any of it happens.

### Messages that had no next step now have one

A machine with no Microsoft Edge showed "Place a Fixed Version Runtime in runtimes/webview2/", which
is not an instruction anyone can follow without knowing the product. It now says to install Edge, or
to take the Self-Contained edition, and gives both addresses. Deleting in the local file browser now
states that it bypasses the Recycle Bin and takes a folder's whole contents.

### The crash report finally contains something

The unhandled-error dialog ended with "Full details have been written to the log file". It never
said where the file was, and the promise was not kept: the log recorded only the same sentence you
had just read, with no exception type, no stack and no inner cause. Anyone who did everything right
sent in a file that added nothing.

The log now holds the full detail and is written out immediately, and the message names the folder
so you can paste it into the File Explorer address bar.

### The welcome tour ends where you can start

Its second step is about the built-in tools and navigated to Settings instead, and the tour then
finished there. The panel inviting you to add your first session was never seen. On the same screen,
the Save button was pressable on the protocol picker, where it and the Enter key both did nothing.

### The download page says what the .msi is for

Five files are published and the .msi sorts first, so it was the first thing a visitor saw. It was
also the only one with no description. It installs for the whole machine, needs an administrator,
and is not updated by Heimdall's own updater. It now says so, and will on every future release.

### There is now a user guide

Everything in docs was written for someone building Heimdall. The troubleshooting index describes
itself as a record of issues met during development and is organised by internal cause, so a white
RDP screen sends you looking for "Disconnect Code 4360".

USER-GUIDE.md answers what actually gets asked: making a first connection, what the host key prompt
means and when to refuse it, where passwords are kept, moving files, what the common failures mean,
how to find a log to attach to a report, and how to update. It exists in English and in French.

The README is now a front page rather than a 465-line feature catalogue. The catalogue is still
there, in docs/FEATURES.md.

### Under the surface

Two conventions are now enforced by tests rather than by memory. One rejects a tool view that
answers a failed user gesture with a log line alone, which is how six of the silent copies above
were found after a first sweep missed them. The other rejects typographic substitutes in the
documentation, recursively, and asserts separately that it reaches subdirectories, because a hand
sweep once passed while two of them were never opened.
