### Changes

**Two audits in one release: the updater and the application exit, then SFTP, FTP and FTPS**

Both subsystems were read end to end on 2026-09-06 and every finding was either fixed, parked with
a written reason, or recorded in the security notes. The updater and exit audit found 67 items,
4 of them severe; the SFTP, FTP and FTPS audit found 76, 8 of them severe. Every fix ships with a
test that fails against the defect, and each decision was proved against a named mutant.

- **The updater comes back even when its script never starts.** The relauncher's bootstrap had no
  failure path: a Security module that would not import, a tampered script, or a script that did
  not parse ended the update with the application already closed and nothing restarted. The
  bootstrap now records the failure and relaunches the application itself. It no longer installs
  over a running application either: after the wait, it checks the process and refuses with its
  own message, instead of letting the installer force-close a live session.
- **The update source is pinned.** The repository the updater reads came from settings.json, which
  a user-level write could steer into an installer running elevated; it is a constant now, and
  downloads are confined to GitHub origins. A portable or MSI copy is no longer offered an
  installer that cannot replace it.
- **Closing saves first.** Installing an update, closing a floating session window, or ending the
  Windows session no longer discards what an ordinary close would have saved, and floating windows
  stop prompting while the application is already shutting down.
- **A chmod on a listed symbolic link no longer changes its target**, anywhere on the server. Server
  names are validated where they enter the file browser, so a name with a separator or a control
  character never becomes a path an operation trusts.
- **Uploads work on servers that allow SFTP but refuse exec** (ForceCommand internal-sftp, chrooted
  accounts): the metadata check runs only when the destination exists, and a refused exec channel
  is reported as such instead of blocking every upload.
- **A listing that fails no longer sends a batch as replacements.** A dropped connection during the
  pre-upload inventory used to read as "no conflicts", and every file went out over whatever was
  there. The batch is refused before its first byte. Names compare case-insensitively unless the
  server shows it tells case apart, and an upload that fails part way says how many files landed.
- **FTPS trust is stricter and clearer.** A pin the system validated is refused when its revocation
  status can no longer be checked; a pin that expired or was revoked says so in its own words;
  pins are keyed by lower-cased host; TLS 1.2 or 1.3 only; the cleartext warning shows for
  anonymous FTP too. A changed FTPS certificate is refused without a prompt, and the prompt that
  claimed to handle that case, which could never be reached, is gone.
- **Closing a pane no longer deletes a file open in an external editor.** The close guard asks when
  a file is open outside, and the local copy stays while that editor runs. The local editor pane
  asks before closing on unsaved text, gains Ctrl+S and Ctrl+W, and opens Latin-1 files.
- **A right-click selects the row it lands on** in both file browsers; the context menu used to act
  on the row selected before the click. Chmod shows and applies the setuid, setgid and sticky bits.
  Back navigation, link double-clicks, and the operations log (chmod is journaled now) are fixed.
- **Privileged transfers name the missing tool** on a server without GNU coreutils, and the
  ownership probe works with BSD stat.
- **Documentation.** Features, user guide, security notes and troubleshooting describe every
  behaviour both audits changed, in English and French.
