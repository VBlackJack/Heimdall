## Francais

### Changements

**Les certificats que vous avez approuves**

- **Vous pouvez enfin voir et revoquer ce que vous avez approuve.** Heimdall retient le certificat
  que vous acceptez pour un bureau distant et le conserve d'un demarrage a l'autre. Rien ne
  permettait de consulter cette liste ni d'en retirer une entree : les deux methodes du magasin qui
  le font n'avaient aucun appelant. Reglages, Bureau a distance, onglet Certificats.
- **Oublier une entree demande confirmation, et la confirmation dit ce qu'elle fait** : elle retire
  ce certificat de ce profil, et rien d'autre. Les autres certificats approuves pour le meme
  serveur restent approuves - ce qui est la verite du code, et pas la promesse plus large qui avait
  ete ecrite d'abord.
- **Une entree dont le profil n'existe plus s'affiche** sous son identifiant, avec un badge, plutot
  que d'etre cachee : une confiance orpheline est justement ce qu'on vient nettoyer. Un inventaire
  illisible n'est pas une suppression, et les deux ne se disent plus pareil.

**Une question de certificat ne consomme plus le budget de connexion**

- **Dix sessions qui se reconnectent ensemble ne se perdent plus en route.** Les questions de
  confiance sont posees une par une ; chaque session armait pourtant son propre budget de 45
  secondes des le depart, si bien que les dernieres de la file expiraient avant meme que leur
  question soit affichee. Le chien de garde est suspendu pendant la verification et repart avant la
  connexion.
- A savoir, parce que l'interface ne peut pas le dire elle-meme : tant qu'une question est a
  l'ecran, elle est modale a l'application. Le bouton Annuler des autres onglets se declare actif
  et ne repond pas. Pendant que la file s'ecoule, c'est le refus de chaque question qui sert de
  sortie.

**Quand une passerelle SSH refuse**

- **Le message dit ce qui a ete observe, apres la phrase du serveur et jamais a sa place.** Dix
  tunnels refuses par une meme passerelle affichaient les mots du serveur, "Permission denied
  (password)", et rien d'autre : vrai, et cela envoie chercher du cote des mots de passe. Le
  message ajoute desormais combien de cles un agent joignable portait au moment de l'appel, sans
  affirmer que l'agent est la cause - un mot de passe enregistre peut tout aussi bien etre faux.
- **Le controle prealable regarde toute la chaine.** Il existait deja et refusait avant de composer
  un profil qui depend d'un agent absent, mais ses deux appelants n'examinaient que le premier
  saut. Une chaine dont la seconde passerelle depend de l'agent passait au travers et echouait
  apres coup.
- **Dix echecs identiques ne sont plus dix rapports.** Les repetitions d'une meme passerelle, d'un
  meme code et d'un meme message passent en Debug avec leur rang, et le rapport suivant dit combien
  ont ete retenues.
- **Le journal ne noie plus la ligne qui compte.** Chaque rafraichissement de configuration
  deversait environ cinq cents avertissements de validation sur une seule ligne. Elle les compte et
  cite les cinq plus severes, le detail complet passant en Debug.

**Une annulation tient**

- **Annuler une connexion pendant que la surface se prepare annule vraiment.** La reprise qui
  attend la disposition de la surface repartait comme une nouvelle tentative autorisee par
  l'utilisateur et effacait l'annulation posee juste avant. Le defaut etait present dans la
  v2026.090201.

### Pourquoi

Cette version corrige ce qu'un audit de la surface RDP avait laisse ouvert, et ce que l'usage a
trouve ensuite. Deux choses valent d'etre dites.

La premiere : une release publiee le matin meme portait un defaut que ses propres tests ne
pouvaient pas voir. Trois verifications de cette campagne lisaient le texte source au lieu
d'observer le comportement, si bien que commenter l'appel garde les laissait vertes. Elles ont ete
remplacees, et la decision qu'elles surveillaient a ete sortie du code de la vue vers un type qui
peut etre exerce directement.

La seconde : rien ne verifiait qu'une cle de traduction citee depuis le code existe dans le
catalogue. Le XAML etait couvert, les cles mortes etaient couvertes, ce sens-la ne l'etait pas -
une cle pouvait donc s'afficher telle quelle a l'ecran. Une garde le verifie maintenant, regle de
decouverte par regle de decouverte, de sorte qu'une regle qui cesse de trouver quoi que ce soit
echoue sous son propre nom.

## English

### Changed

**The certificates you have approved**

- **You can now see and revoke what you approved.** Heimdall remembers the certificate you accept
  for a remote desktop and keeps it across restarts. Nothing could show you that list or take an
  entry back: the two store methods that do it had no caller. Settings, Remote Desktop,
  Certificates tab.
- **Forgetting an entry asks first, and the question says what it does**: it removes that
  certificate from that profile and nothing else. Other certificates trusted for the same server
  stay trusted - which is what the code does, rather than the wider promise first written.
- **An entry whose profile no longer exists is shown** under its identifier with a badge rather
  than hidden: an orphan trust is exactly what someone comes to clean up. An unreadable inventory
  is not a deletion, and the two no longer read the same.

**A certificate question no longer spends the connect budget**

- **Ten sessions reconnecting together no longer lose the stragglers.** Trust questions are asked
  one at a time, yet every session armed its own 45-second budget at the start, so the ones at the
  back of the queue expired before their question was even shown. The watchdog is suspended for the
  check and resumes before the connect.
- Worth knowing, because the interface cannot say it itself: while a question is on screen it is
  application-modal. The Cancel button on other tabs reports itself enabled and does not respond.
  While the queue drains, refusing each question is the way out.

**When an SSH gateway refuses**

- **The message says what was observed, after the server's sentence and never in its place.** Ten
  tunnels refused by one gateway showed the server's words, "Permission denied (password)", and
  nothing else: true, and it sends the reader to passwords. The message now adds how many keys a
  reachable agent held when the gateway was dialled, without claiming the agent is the cause - a
  saved password can equally be wrong.
- **The pre-flight looks at the whole chain.** It already existed and already refused, before
  dialling, a profile depending on an absent agent - but both its callers examined only the first
  hop, so a chain whose second gateway needed an agent went through and failed afterwards.
- **Ten identical failures are no longer ten reports.** Repeats of the same gateway, code and
  message go to Debug with their rank, and the next full report says how many were held back.
- **The log no longer buries the line that matters.** Every configuration refresh dumped some five
  hundred validation warnings onto one line. It now counts them and quotes the five most severe,
  with the full detail at Debug.

**A cancellation holds**

- **Cancelling while the surface is still being laid out actually cancels.** The retry that waits
  for the surface presented itself as a new user-authorized attempt and cleared the cancellation
  set moments earlier. The defect was present in v2026.090201.

### Why

This release closes what an audit of the RDP surface left open, and what using the product found
next. Two things are worth saying.

First: a release published the same morning carried a defect its own tests could not see. Three
checks in this campaign read source text instead of observing behaviour, so commenting the guarded
call out left them green. They were replaced, and the decision they watched was moved out of the
view's code-behind into a type that can be exercised directly.

Second: nothing verified that a translation key named from code exists in the catalogue. XAML was
covered, dead keys were covered, that direction was not - so a key could reach the screen as its
own identifier. A guard checks it now, discovery rule by discovery rule, so a rule that stops
finding anything fails under its own name.
