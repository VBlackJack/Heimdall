# Root folder creation and rename check the folders on their way

This release brings the last two root actions of the SFTP browser, creating a folder and renaming an entry, under
the same path checks as the others, gives a new file written as root the mode `sudo cp` gave it, and makes sudo
answer in English on every server.

## What you will see

### Security

- **Creating a folder and renaming an entry as root check the folders on their way.** Like the other root
  actions since v2026.111701, they reach the entry one folder at a time from the root folder and act from the
  folder they reached. A symbolic link on the way is followed only when the link and the folder holding it
  belong to root or to you, and that folder cannot be written by other accounts. Any other link is refused,
  and the message says so.

### SFTP browser

- **A name that is already taken is reported.** Creating a folder as root under a name that exists now says
  so, instead of reporting the folder as created. A rename as root keeps your choice: without Replace, an
  existing name is reported and nothing moves.
- **A new file written as root can be read by the services that need it.** An upload or an editor save that
  creates a file as root used to leave it readable by root only (mode 0600), so a web page or a configuration
  file could not be read by the service meant to use it. A new file now gets mode 0644, as `sudo cp` gave it,
  where the file system allows it. In a folder with a default ACL, the file keeps what that ACL gives it. A
  file that replaces another still keeps its owner, mode, timestamps and extended attributes.
- **Password and permission errors are recognized whatever the server's language.** sudo is now started in
  the C locale, so its messages are in English on every server. On a server set to another language, a
  refused password now stops a batch after the first entry, as it already did on English servers.

### Documentation

- **SECURITY and ARCHITECTURE describe the new rules**, in English and French.

## What to know before you upgrade

- **A secret uploaded as root as a new file is readable by every account** until you change its permissions,
  as with `sudo cp`. The root permission change of the browser does that without following a link.
- **Creating a folder or renaming as root now needs GNU coreutils on the server**, like the other root
  actions. On BusyBox or BSD it is refused instead of run.
- **A link that belongs to another account, or a link in a folder other accounts can write, is refused** when
  creating a folder or renaming as root. Open the real path.

## Verified

- Run as root on Debian 12 (dash and bash) and AlmaLinux 9, with the commands exactly as Heimdall builds them:
  creating a folder and renaming through a link made by root and through your own link work, Replace works, a
  folder can be renamed; an existing name is reported with nothing changed; a link owned by another account
  is refused with nothing changed; nothing is left behind.
- The new-file mode and the sudo locale were run under Linux as a regular account (umasks, setgid folder,
  folders with a default ACL, sudo started from a French locale), not yet as root on a real server.
- Not tried on screen: the new messages in the application, French and Spanish.

## Limits that remain

- On a folder with a POSIX ACL the mode bits show the ACL mask, and NFSv4 ACLs are not seen.
- The checks before a rename that look for an existing name read the path as given.
