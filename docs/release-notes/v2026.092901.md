# An SSH terminal that was stuck at 80 columns

This release carries one fix. If your SSH sessions go through Plink, which is the
case when you sign in with a key held by Pageant, or when Heimdall retries after
a refused sign-in, the remote terminal now opens at the size of the pane you are
looking at instead of 80 columns by 24 lines.

## Long command lines no longer overwrite themselves

On that path the remote shell believed the terminal was 80 columns wide, however
wide the pane actually was. It wrapped every line at column 80, and a long
command line came back onto itself and wrote over its own beginning, so what you
saw was no longer what you were editing.

Plink on Windows takes the terminal size only from its saved configuration, never
from the window it runs in, and Heimdall was not giving it one. The session now
opens with the real width and height of the terminal pane, and `stty size` on the
server answers with them.

On a fresh tab the terminal is still drawing itself when the connection starts,
so Heimdall waits for it to report its size before starting Plink. The wait is
short in practice and is bounded by a new setting, `PlinkInitialSizeWaitMs` in
the settings file: 3000 ms by default, anywhere from 500 to 30000, and 0 turns
the wait off. When the terminal has not answered in time, the session opens at
80x24 as it did before, and the log says why.

## What this does not fix yet

The size is sent once, when the session opens. Resizing the pane afterwards is
still not passed to the server on this path: Plink has no way to send a new size
once it is running. If you widen or narrow the pane during a session, either
reconnect, or type `stty cols <width> rows <height>` in the remote shell.

SSH sessions that do not go through Plink are unchanged: they already followed
the pane when it was resized.

## If the width still looks wrong

The log tells you which way the launch went. The first line below means the size
was applied, the second that it fell back to 80x24 and why:

- `SSH opening the PTY for <profile> at the reported <cols>x<rows>`, followed by
  `[PlinkSizeSession] Created Plink size session <name> carrying <cols>x<rows>`
- `SSH opening the PTY for <profile> at the default 80x24: <reason>`

A reason of `the terminal page did not report its size within ... ms` means the
page loaded more slowly than the wait allows: raise `PlinkInitialSizeWaitMs`. A
warning `[PlinkSizeSession] Could not create the Plink size session` means the
registry refused the step described below; check that your account can write
under `HKCU\Software\SimonTatham\PuTTY\Sessions`, which a policy or a security
product may block. The troubleshooting guide covers this in its section on long
lines wrapping at column 80.

## A short-lived entry in the PuTTY registry

To hand Plink the size, Heimdall writes a temporary PuTTY saved session under
`HKCU\Software\SimonTatham\PuTTY\Sessions`, named `HeimdallPtySize-` followed by
a random suffix, at each Plink launch. It is removed as soon as Plink starts
producing output, or otherwise when the session ends or fails to start. It copies your
PuTTY default settings, changes only the terminal size, and never holds a host
name. An entry left behind by a crash is cleared before Heimdall's next SSH
launch, and these entries never appear in the PuTTY import.
