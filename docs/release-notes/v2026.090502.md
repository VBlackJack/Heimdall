### Changes

**An interrupted external launch no longer leaves its password in the Credential Manager**

- **A crash, a kill or an exit inside the cleanup window stranded the entry.** An external
  launch writes a `TERMSRV/<host>` credential for `mstsc.exe` and releases it from a deferred
  task that dies with the process. Whatever was left behind stayed readable until the Windows
  session ended. The temporary `.rdp` file has had a janitor since v2026.090201; the half that
  carries the password had none.
- Heimdall now sweeps `TERMSRV/*` at startup and before every external launch, deleting the
  domain-password entries whose Heimdall marker is older than the live-launch window, whatever
  process wrote them. A marker without a timestamp, from an older build, is left alone. The
  cleanups still pending when Heimdall exits are released at exit.

**Two embedded sessions prompting at once each fill their own prompt**

- **The second session's prompt could receive the first session's password.** Two embedded
  sessions raising the Windows Security prompt at the same time show two identical dialogs in
  one process, and the autofill chose between them by title, then by foreground window, neither
  of which names a session.
- The prompt is owned by a window of the control that raised it, so the scan now records each
  candidate's owner and only fills a prompt owned by the session's own surface. A prompt owned
  by another session is left to that session. When no candidate carries an owner at all, the
  previous choice applies.

**Replacing a profile from a .rdp file keeps what the file cannot say**

- **The Replace resolution of the .rdp import reset fourteen fields a .rdp file cannot
  express**: the fixed resolution the import itself reports as a skipped mapping, the domain,
  the aspect ratio, anti-idle, the admin and full-screen switches, the post-connect steps, and
  the saved password, while the preview only mentioned the file's own password blob.
- The existing profile is now cloned and the file's settings are written onto the clone: a field
  the file names is overwritten, a field it does not name keeps the value the user had.

**Smaller Remote Desktop corrections from the same audit**

- A connect attempted while the vault is locked says "unlock the vault" in the session header,
  as the Citrix launcher already did, instead of a generic failure followed by an exception
  message.
- The status line and the health dot announce to a screen reader once per change. Every handler
  on a transition rewrote them with the same words, and one connection announced six times.
- A tab closed while the connect attempt was flushing its layout no longer touches a control
  already handed back to the pool.
- The letterbox hint falls back to its locale key rather than an English sentence.
- The resilience settings are recorded once and written by the connect, instead of re-applying
  every redirection setting a third time before each connection.
- The vtable slot the multi-monitor switch is written through is pinned against the control's
  type library, as the event identifiers already were.

**The vault tests own their baseline**

- Six Core test classes and eight App test classes drive the static vault state of
  `CredentialProtector`. Each member now establishes a declared baseline on entry and restores
  it on exit, instead of inheriting whatever the previously scheduled class left behind. A guard
  keeps the rule closed over the test sources. No product behaviour changes.

### Notes

- **What remains open, and why.** The pool of Remote Desktop controls keeps two idle controls
  with no expiry, which retains memory after every tab is closed; that is a change of the
  control lifecycle and gets its own pass. The middle-dot separator in disconnect codes is
  unchanged. Whether the generated `.rdp` file needs `drivestoredirect` in addition to
  `redirectdrives` for drive redirection in the external client has not been measured on a
  target; the file is unchanged until it is.
- **An assumption to know about.** The prompt discriminator assumes the Remote Desktop control
  parents its Windows Security prompt to one of its own windows. If it does not, no candidate
  carries an owner and the previous behaviour applies; the log then reads `no-match-owner` for
  a prompt the session refused to fill.
- See SECURITY, section "RDP server certificate trust", for the `TERMSRV` credential sweep, and
  the Settings FAQ entry ".rdp file and credential cleanup delay".
