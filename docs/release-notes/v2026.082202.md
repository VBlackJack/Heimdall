A small release with one change, made because the previous one admitted the problem in writing and
leaving it there would have been worse than not mentioning it.

### The bitmap caching checkbox now says what it does

"Bitmap caching" described something the checkbox does not control. It decides whether the bitmap
cache is written to disk between sessions, so that reconnecting can reuse it instead of redrawing
everything. It has never had any effect on the cache held in memory, and no setting in Heimdall
does.

The tooltip was wrong in the same direction, and worse. It promised reduced bandwidth and better
responsiveness over slow links, which is what an in-memory cache would give you. Anyone looking for
memory to reclaim was therefore pointed at the worst move available: turning this off costs you the
disk cache and returns nothing.

The setting is now called "Keep bitmap cache on disk", and the tooltip describes what it actually
does, including the fact that switching it off frees no memory. The name changed everywhere it
appears: the settings screen, the server dialog, both screen-reader labels, and the reconnection
error message that used to tell you to disable bitmap caching by its old name.

The setting itself is unchanged. If you had it on, leave it on.
