# The Open Ports tool reads a table again when it grows while it is read

A small maintenance release. One fix can be seen, in the Open Ports tool; the rest makes the way
Heimdall reads the system's connection tables more robust and changes five of the project's tests:
four lose a known cause of intermittent failure or of a hang, and the fifth only reports more
detail when it fails. Apart from the Plink tunnel check described below, nothing changes in how
sessions connect.

## What you will see

### Tools

- **Open Ports reads a table again when it grows during the read.** The tool reads four tables
  from Windows: TCP and UDP, each for IPv4 and IPv6, and shows them as one list. For each one it
  asked Windows how large the table was, then read it once at that size. If a connection or a
  socket appeared between the two steps, the table no longer fitted, the read failed, and the rows
  of that table were left out without a word: for example every IPv4 TCP row missing until you
  pressed Refresh again (the tool does not refresh on its own). The tool now reads the table again
  at the size Windows then reports, at most four reads in all; if the table is still too large
  after the fourth, its rows are left out as before.
- The same tool now refuses a table whose announced number of rows would run past the memory
  Windows filled; before, it read that many rows anyway. The rows of such a table are left out of
  the list, as with any failed read. This is a safeguard: no such table has been observed.

### SSH tunnels through Plink

- When a tunnel is started through Plink, Heimdall checks that a listener on the forwarded port
  belongs to the Plink process it started. That check read the TCP table the same way. When that
  read failed, the attempt was inconclusive and the check tried again one interval later (two
  seconds by default), so a tunnel Plink had opened was accepted later rather than stopped, unless
  the read failed on every attempt; a tunnel stopped because another program held the port could
  be logged with a less precise reason. The read is now retried the same way. The message shown
  when the check does not pass is unchanged: "The configured Plink executable did not open the
  forwarded port itself. The tunnel was stopped."

## How this was checked

- By automated tests that hand the Open Ports reader, for each of its four tables, a table in the
  real Windows layout which grows once, grows on every attempt, or fails for another reason, and
  that do the same for the tunnel check's IPv4 table (its IPv6 table only for growth once). They
  also check, through a stand-in allocator, that every block of memory taken is given back.
- On a real machine: a test that runs the tool's real reading code returned rows. The tool's
  window itself was not opened.
- The project's test suite passed on the developer's machine and in the automated build of each
  change.
- Not reproduced: the failure itself. It needs the table to grow between two system calls, which
  could not be provoked on demand.

## Upgrade notes

- Nothing to do. No setting, no stored data and no dependency changes in this release.
- If Open Ports showed a list that looked too short on a machine with many connections, pressing
  Refresh again usually brought the rows back; this release makes that much less likely to be
  needed, without ruling it out.
