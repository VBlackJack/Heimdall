# Shared MobaXterm session files, with passwords each person keeps

Teams that keep their sessions in a shared MobaXterm file can now use that file directly in
Heimdall. This release also fixes the VNC view only setting, makes the session tree follow a
disconnection, and brings back the highlights of the first-run tour.

## Shared MobaXterm sessions

- **Point Heimdall at your team's `.mxtsessions` file** (Settings > General > Shared session
  sources). Its sessions appear in the tree under a root of their own and stay read-only: they
  keep being edited in MobaXterm, and Heimdall follows the file when it changes. A step-by-step
  guide is in [docs/MOBAXTERM-SHARED-SESSIONS.md](https://github.com/VBlackJack/Heimdall/blob/v2026.101701/docs/MOBAXTERM-SHARED-SESSIONS.md).
- Variables such as `[DAS]` in a user field resolve to each person's own login (Settings >
  General > MobaXterm import variables).
- When the file cannot be read, for example while a synchronized folder is not ready yet, the
  sessions come from an offline copy of the last good read, and the source says so.
- An import report lists what the file's maintainers may want to fix: skipped sessions,
  unresolved variables, a session named after one machine that reaches another, unusual
  gateways and duplicate hosts. It can be copied or exported as CSV.
- The login command of a session, such as `sudo su - www`, runs after connecting once you have
  approved it, and Heimdall asks again when the file changes it.
- **Passwords stay personal.** A shared file never gives Heimdall a password. When your SSH agent
  offers no key, Heimdall asks for the password of the bastion, then of the server, with a
  **Remember this password on this computer** box, as in MobaXterm. A remembered password stays on
  this computer, encrypted for your Windows account. It is never exported, never written to the
  shared file, and never sent to a host or login it was not given for. A password the server
  refuses is forgotten. Each source has **Forget saved passwords**, and removing a source forgets
  its passwords.
- The SFTP pane that opens beside a shared SSH session signs in with the same passwords.

## MobaXterm import (Settings > Import)

- The session type is now read from the right field, and jump hosts become SSH gateways.
  **Only SSH and RDP sessions are imported**: FTP, SFTP, VNC and Telnet sessions, which used to
  come in with the wrong type, are listed as unsupported in the import summary.

## Sessions

- **The session tree follows a disconnection.** When an SSH terminal or an SFTP pane disconnects
  while its tab stays open, the row's dot turns off instead of staying green until the tab is
  closed, and it turns back on when the pane reconnects.
- A disconnected SFTP pane shows one Disconnected message instead of two stacked ones.

## VNC

- **View only now blocks input.** A VNC server set to View only still sent the keyboard, the
  mouse and the clipboard to the remote host.
- The display controls (clipboard, scaling, quality) move into the session header instead of
  covering the top right corner of the remote screen, where its windows keep their buttons
  (issue #594, contributed by @Anghios).
- Each quality preset now changes the picture: it sets the image quality as well as the
  compression.

## Also

- The first-run tour highlights the session list, the add button and the search box again. On a
  fresh profile its first three steps showed their card with nothing highlighted.
- Saving profiles and settings no longer fails now and then when another program, such as an
  antivirus or a sync client, reads the file at the same moment.
- Dependency update: System.Security.Cryptography.ProtectedData 10.0.13.
