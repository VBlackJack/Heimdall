## Francais

### Changements

**La question du certificat est posee dans la session qui la pose**

- **Elle apparait dans l'onglet concerne, plus au milieu de la fenetre principale.** Quand
  plusieurs sessions s'ouvrent ensemble, la question portait sur l'une d'elles sans dire laquelle :
  on pouvait approuver le certificat d'une machine en croyant repondre pour une autre. Chaque
  question s'affiche desormais dans son propre panneau, et une derniere ligne nomme l'onglet et la
  fenetre d'ou elle vient.
- **Deux profils portant le meme nom ne produisent plus deux questions identiques.** La question
  indique la passerelle empruntee - "Atteint via : Paris datacentre" - et deux onglets homonymes
  sont numerotes. Sans cela, deux "Production" atteignant deux sites differents presentaient le
  meme sujet et la meme empreinte, sans rien pour les distinguer.
- **La touche Entree repond.** Le bouton qui a le focus s'active, y compris "Ne pas se connecter".
  Il ne se passait rien du tout auparavant.

**Ce que vous approuvez reste au profil qui l'a approuve**

- **Une approbation donnee pour un profil ne peut plus en atteindre un autre.** L'identifiant sous
  lequel une session tourne n'est pas celui du profil, et trois facons de retrouver l'un a partir
  de l'autre se sont revelees fausses tour a tour : un profil importe pouvait porter un identifiant
  de la meme forme, un profil supprime pendant sa propre connexion devenait introuvable, et un
  import pouvait reprendre un identifiant de session lu dans le journal. Le profil retient
  desormais de quel profil il est une copie, au moment ou son identifiant est remplace.
- **Un panneau divise partage la confiance de son profil.** Approuver durablement depuis un
  panneau divise vaut pour le profil, donc la question ne revient pas au panneau suivant.
- **Le bouton "Modifier le profil" d'un panneau divise ouvre l'editeur** au lieu de repondre
  "serveur introuvable".

**Le trajet affiche est celui que le tunnel a reellement emprunte**

- **Un tunnel reutilise indique sa vraie passerelle.** La reutilisation se decide sur les
  identifiants des passerelles, qu'une modification laisse intacts : la connexion qui reutilise un
  tunnel ne peut donc pas retrouver le trajet toute seule. Chaque tunnel retient desormais la
  chaine par laquelle il a ete ouvert, au moment de l'ouverture, et la rend a qui le reutilise.
- Cela vaut pour toutes les manieres d'ouvrir un tunnel, y compris un tunnel ouvert a la main
  depuis l'onglet Tunnels et le repli plink.

**A la fermeture, toutes les sessions se ferment**

- **Aucune session ne reste ouverte a la sortie de l'application.** La demolition de l'etat d'un
  panneau precedait la deconnexion de son hote et n'etait pas protegee ; a la fermeture elle
  echouait a chaque fois, et la premiere emportait toutes les suivantes. Aucun hote n'etait ferme,
  aucune vue n'etait liberee. Cela se produisait a chaque fermeture avec une session ouverte.

### Notes

- La question du certificat n'est posee que pour les profils dont l'authentification au niveau
  reseau (NLA) est desactivee. Avec NLA active, c'est le client Bureau a distance de Windows qui
  pose la sienne, comme avant.

## English

### Changes

**The certificate question is asked in the session that is asking**

- **It appears inside the tab it concerns, not in the middle of the main window.** When several
  sessions open together, the question was about one of them without saying which: you could
  approve a certificate for one machine believing you were answering for another. Each question is
  now drawn in its own pane, and a last line names the tab and window it came from.
- **Two profiles with the same name no longer produce two identical questions.** The question names
  the gateway the connection was reached through - "Reached through: Paris datacentre" - and two
  same-named tabs are numbered. Without it, two profiles called "Production" reaching two different
  sites showed the same subject and the same fingerprint, with nothing to tell them apart.
- **Enter answers.** The focused button activates, including "Do not connect". Nothing at all
  happened before.

**What you approve stays with the profile that approved it**

- **An approval given for one profile can no longer reach another.** The identifier a session runs
  under is not the profile's own, and three ways of recovering one from the other turned out to be
  wrong in turn: an imported profile could carry an identifier of the same shape, a profile deleted
  during its own connection became unfindable, and an import could arrive under a session
  identifier read from the log. A profile copy now remembers which profile it is a copy of, at the
  moment its identifier is replaced.
- **A split pane shares its profile's trust.** Approving permanently from a split pane counts for
  the profile, so the next pane is not asked again.
- **A split pane's "Edit profile" button opens the editor** instead of answering "server not
  found".

**The route shown is the one the tunnel actually took**

- **A reused tunnel names its real gateway.** Reuse is decided on gateway identifiers, which an
  edit leaves untouched, so the connection reusing a tunnel cannot work out the route by itself.
  Each tunnel now remembers the chain it was dialled through, at the moment it is opened, and hands
  it back to whoever reuses it.
- This holds for every way a tunnel can be opened, including one opened by hand from the Tunnels
  tab and the plink fallback.

**At exit, every session closes**

- **No session is left open when the application quits.** Tearing down a pane's state came before
  disconnecting its host and was unguarded; at exit it failed every time, and the first failure
  took every session behind it. No host was closed and no view was released. This happened on every
  shutdown with a session open.

### Notes

- The certificate question is only asked for profiles with Network Level Authentication (NLA)
  disabled. With NLA on, Windows' own Remote Desktop client asks its own, as before.
