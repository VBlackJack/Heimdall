# Notes no longer lose text typed during a save, updates check every redirect, and closing sessions is safer

This release fixes a way notes could lose what you were typing, tightens the updater, the file share and the
embedded web views, makes closing SSH, VNC and Citrix tabs more reliable, and makes the log viewer and terminal
output much lighter on the window.

## What you will see

### Notes

- **Text typed while a note is being saved is kept.** Before, a note could be marked as saved even though you had
  typed more while the file was being written, and those last characters were never saved.
- **Switching notes, deleting, renaming or moving a note right after typing no longer loses or resurrects
  anything.** An autosave that was waiting during a delete no longer brings the deleted note back.
- **Notes are written more safely.** The file is written next to the note and swapped in, so a crash during a save
  leaves the previous version intact. Permissions of notes in shared or synchronized folders are left as they are.

### Log viewer and terminal

- **The log viewer no longer freezes the window on large files.** A 20 to 50 MB log is read and filtered in the
  background, a slow filter expression shows an error instead of failing, and a line being written is no longer
  split in two or followed by a blank line.
- **Large terminal output is lighter on the window.** Output is sent to the terminal in batches, with the same
  typing response as before.
- **A quoted terminal font list such as "Cascadia Code", Consolas works again** instead of breaking every terminal
  tab.

### Sessions

- **Closing an idle SSH session is immediate.** Before, closing it could wait for a timeout and write a warning in
  the log.
- **Closing a VNC tab while it connects no longer leaves a ghost connection or an error.** The reconnect message
  now takes the keyboard focus, so a Space or Enter typed as the session drops does not reconnect by accident.
- **Closing a Citrix tab while its window is being captured no longer touches a view that is already closed**, and
  one failing cleanup step no longer skips the following ones.
- **The SSH gateway tunnel is released on every kind of failure.** Before, some failures left a tunnel reference
  behind.
- **Accepting a changed SSH host key replaces the old entry for good** when it was stored hashed. Before, the old
  entry came back at the next start.
- **Privileged SFTP transfers work with paths containing "!"** when the server login shell is csh or tcsh.

### Messages and overlays

- **Toasts and overlays are visible above open sessions.** Before, the RDP notices (including "certificate not
  verifiable"), the VNC and web loading bars, the onboarding screen and the .rdp drop area could be hidden behind
  the session.
- **The restore dialog no longer says that only SSH, RDP and SFTP tabs come back.** Every session tab is
  restored, whatever its protocol; tool tabs are not.

### Import and clipboard

- **A damaged or locked file during session import (RDP files, OpenSSH config, PuTTY) shows a clear error** instead
  of the generic error dialog. If the import worked but the list could not be refreshed, a message says so.
- **A copied one-time (TOTP) code and a copied file share link stay out of the Windows clipboard history and the
  cloud clipboard.**

### Network diagnostics

- **Ping and SNMP walk refuse a host or OID that would be read as a command option** (for example one starting
  with "-"), before anything is sent through an SSH gateway. Names that worked before, including internationalized
  host names, still work, and spaces around a host are ignored.
- **Symbolic SNMP names without a gateway are refused with a message explaining why.** Direct SNMP only takes
  numeric OIDs.

## Security hardening

- **Updates check every redirect.** Each step of a redirect must stay on an allowed GitHub address over https, with
  at most 5 steps, and a download is capped at the size the release declares (1 GiB when unknown). The SHA-256
  check of the file is unchanged.
- **The temporary file share sends protective headers.** HTML, SVG and XML files are served sandboxed so they
  cannot act on the share page. PDF files still open in the viewer.
- **Embedded web views are locked down the same way**: developer tools, autofill and password saving are off, links
  to other programs are cancelled and logged, and the VNC page has a content security policy.
- **The privilege launcher checks the account behind the token it borrows.** A SYSTEM launch only uses a process
  that really runs as SYSTEM, and a TrustedInstaller launch now works: before, it failed with "No accessible
  token found".

## Reliability

- **The log file can no longer grow memory without limit when it cannot be written** (disk full, file in use). The
  queue is capped, and one line tells how many entries were dropped once writing works again.
- **A configuration read in progress no longer makes a save fail** for the servers file.
- **Finding PowerShell 7 when it is not on the PATH is faster and safer**, searching one folder level deep as
  intended.
- **Reloading the web console during start-up no longer starts it twice.**

## Under the hood

- **Running the test suite no longer brings up a Windows Firewall prompt.** The file share tests listen only on the
  local machine. The file share itself is unchanged.
- **The "!" handling of privileged SFTP commands now lives in one place.** The commands sent to the server are the
  same as before.

## Verified

- Every change was merged with the solution building with no warning, a clean code format check and green CI. New
  tests cover each fix above, and the plink process job now has tests.
- Tried on screen against lab servers: a flood of 300,000 terminal lines arrives complete and in order; a 47 MB log
  file opens in about 3 seconds and filters without freezing; the VNC loading bar shows above the viewer; a VNC
  session connects and renders with its new content security policy, and stopping the server shows the reconnect
  overlay.
- Tried for real: privileged SFTP read and write of a file whose name contains "!" under tcsh, csh, bash and zsh
  login shells.
- Tried on screen: a notice ("Escape sent to remote") shows above a live RDP session; on the VNC reconnect
  overlay, Space and Enter do not reconnect; a note typed in short bursts, with pauses as long as the autosave
  delay, keeps every character. The certificate warning itself was not seen: the test server did not raise it.
