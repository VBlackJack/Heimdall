# Imported sessions stay untrusted until you allow them, and mRemoteNG imports keep their order

This release closes a security gap in how imported sessions become trusted, makes tabs of external
and WinRM sessions tell the truth about their state, and answers a request from the community: an
mRemoteNG tree now keeps the order it had.

## What you will see

### Security

- **Editing an imported session no longer trusts what it runs.** A session that comes from a file
  can start a program on your computer (a local shell with its arguments, working directory or a
  request to run as administrator, a web console's external program, a Citrix ICA file) or type
  commands into the session after login. Heimdall asks before running any of that until you have
  approved it. But opening such a session to change something else, a name for example, and saving
  it marked it as approved, without the commands having been shown: most of them sit on another
  tab of the dialog. Saving an existing session no longer approves what it runs.
- **A notice lists what the session would run.** While a session is not approved and holds
  something that runs, the session dialog shows a notice above its tabs with every such value as
  it will be saved, in full, except a web command too long to show whole, which is replaced by a
  message and cannot be allowed from the notice. Commands typed after login are listed even for a
  kind of session whose dialog does not show them anywhere else.
- Its "Allow to run" button, followed by Save, approves the session. Otherwise Heimdall asks when
  you connect, and accepting that question also approves the session from then on; for commands
  typed after login, that question gives their number, not the commands themselves.
- Characters that can hide or disguise part of a command (line breaks, right-to-left marks,
  zero-width characters) are shown as visible codes in the notice. The question asked when you
  connect now does the same for the Citrix ICA file path, and for the local command now also for
  right-to-left marks, zero-width and other invisible characters; it already did so for line
  breaks and tabs.
- A session you create yourself in the dialog is approved from the start, as before. So is a quick
  connection or a discovered host that you save as a session.

### Sessions and tabs

- **A tab opened with "Connect (external mstsc)" follows the mstsc window.** Its status stayed on
  "External client launched", with a loading spinner, for as long as the tab existed, and closing
  the tab asked about a connected session long after the mstsc window was gone. When mstsc closes,
  the tab now reads "Disconnected" and shows the usual disconnected panel, with Reconnect, Edit
  profile, Copy error and Close. In a tab split into panes, that panel does not offer Reconnect
  for such a pane, because reconnecting one pane cannot start mstsc again: close the pane, then
  open the session again.
- **Quitting asks about embedded WinRM sessions too.** With only WinRM tabs open, quitting Heimdall
  closed them without asking, while closing one of those tabs asked first. The "Sessions to
  close: ... Still connected: ..." question asked when quitting now counts them. External clients
  are not counted: Heimdall does not close mstsc, PuTTY or a browser it started when it quits, but
  a client connected through a tunnel that Heimdall opened loses that tunnel when Heimdall quits.
- **A failed WinRM sign-in leaves a tab you can reconnect.** After a wrong password or a refused
  access, the error text could arrive after the session had ended and put the tab back into a
  running state: Reconnect was hidden and Disconnect was shown, with nothing left to disconnect.
  The tab now stays ended, with Reconnect shown and Disconnect hidden; the error text stays in the
  terminal output.

### Import and session tree

- **mRemoteNG connection files keep the order of the file.** Folders and sessions imported from
  mRemoteNG show in the order mRemoteNG lists them, instead of alphabetically. In a folder that
  already holds sessions or sub-folders, what you had keeps its place and the imported items come
  after it. Where the result is what the tree would show anyway, nothing is written: a new folder
  whose items are already alphabetical in the file, with no two of the same name, stays an
  ordinary alphabetical folder.
- **"Sort A to Z" puts a level back in alphabetical order.** The menu of a folder offers "Sort A
  to Z" when its direct sessions or direct sub-folders were arranged by hand or by an import; the
  menu of "(No Folder)" offers it when its sessions were; the menu of the tree's empty area offers
  "Sort top-level folders A to Z" when the top-level folders were. It works one level at a time
  and leaves what is arranged deeper alone. It can be undone from the undo bar, like a move or a
  reorder, unless that level was arranged again in between. Shared folders are read-only and do
  not offer it.
- When nothing is typed, the command palette now suggests sessions in the order of the tree, after
  the ones you connected to recently; when you type, equal matches come in the order of the tree.
  It used a single ranking across all folders (manual place, then name), which after an import in
  file order would have put the first session of every folder first.

### Tunnels through Plink

- The check that a forwarded port was opened by the Plink process Heimdall started now refuses a
  system table whose announced number of rows would run past the memory that was read, instead of
  reading it. That read then counts as a failed check, as whenever ownership cannot be
  established: the check is tried again, and the tunnel is refused if ownership still cannot be
  established. This is a safeguard: no such table has been observed.

## How this was checked

- Each fix and feature comes with automated tests, which the pull requests report were seen to
  fail with the code they protect removed (for the Plink safeguard: nine of its tests fail with
  the check disabled). The dependency updates change no application code; the whole test suite was
  run after each one. The automated build, which runs the test suite except the tests that need a
  desktop, passed on every pull request, and every pull request except the Plink safeguard records
  a full local run that passed.
- The trust change was reviewed twice: once on the design before any code, which found nine
  defects in the first remedy, and once as a security review of the result, which found no way
  around the notice; its findings were fixed. One older path remains: accepting the question asked
  when you connect approves the session, and for commands typed after login that question shows
  their number, not the commands.
- Not tried on screen when these notes were written: the notice in the session dialog (its place
  above the tabs, long lists, French and Spanish lengths, keyboard order, screen readers), the tab
  of a closed external mstsc, a failed WinRM sign-in, the "Sort A to Z" menus (where they sit,
  focus, the undo bar text, screen readers), an import of a real mRemoteNG file, and the look of
  the application with ThemeForge.Theme 2.2.0.

## Upgrade notes

- **Approvals given by an earlier save stay.** An imported session that was opened and saved in
  the session dialog with v2026.060201 to v2026.111401 was approved by that save; this release
  does not take it back.
- **Sessions saved before the trust check existed.** A session last saved by a version older than
  v2026.060201, and neither saved from the session dialog nor allowed at a connect question since,
  carries no approval. If it starts a local program, a web console's external program or a Citrix
  ICA file, or types commands after login, Heimdall already asks before running it when you
  connect, and the session dialog now shows the notice when you edit it. Press "Allow to run",
  then Save, once.
- **Importing the same mRemoteNG file twice adds its sessions twice.** mRemoteNG identifiers are
  not taken from the file. This is not new; it is now written in the documentation.
- **An mRemoteNG folder that holds no session is not created**, and a session placed between two
  folders in mRemoteNG comes after them: Heimdall lists sub-folders before sessions.
- **Importing into a folder can freeze its order.** When the imported items do not fall in
  alphabetical order, the whole folder becomes arranged by hand: a session created there later
  goes to the end. "Sort A to Z" puts it back.
- **A Command Library step in the notice** is shown by the title of its entry and the parameters
  the session supplies, not as the final command.
- **Dependencies updated:** JsonSchema.Net from 7.0.4 to 7.4.0 and ThemeForge.Theme from 2.1.0 to
  2.2.0. The whole test suite passes with them.
