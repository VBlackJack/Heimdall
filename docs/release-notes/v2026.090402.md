## Francais

### Changements

**Les profils deja enregistres sortent de l'espace de noms des connexions rapides**

- **Un profil enregistre avant la version precedente y restait.** La v2026.090401 empechait un
  nouveau profil d'entrer dans l'espace de noms que Heimdall utilise pour les destinations tapees
  dans la palette. Elle ne changeait rien aux profils deja presents dans votre fichier, qui sont
  charges avec l'identifiant sous lequel ils ont ete enregistres. Un tel profil partageait donc
  toujours sa cle de confiance avec une destination tapee.
- **Les certificats approuves suivent le profil.** Renommer le profil sans deplacer ses
  approbations n'aurait rien regle : l'approbation serait restee rangee sous l'ancien identifiant,
  celui que la palette attribue a une destination tapee. La migration au demarrage deplace les deux
  et ne laisse rien derriere.
- Le remplacement d'un profil existant lors d'un import passe desormais par la meme reservation.

### Notes

- Ce qui n'est pas traite, et qui ne peut pas l'etre : une approbation rangee sous un identifiant
  de cet espace **sans profil correspondant** est celle d'une destination que quelqu'un a tapee et
  acceptee ; la supprimer redemanderait une machine deja acceptee. Une approbation ayant appartenu
  a un profil supprime depuis est indiscernable de la premiere. Les deux sont conservees. La
  situation ne peut plus se creer a partir de cette version, puisqu'aucun profil ne peut plus
  entrer dans cet espace.
- Les notes de la v2026.090401 affirmaient que l'isolation des approbations etait exacte a partir
  de cette version. C'etait premature : les trois points ci-dessus restaient ouverts.

## English

### Changes

**Profiles already saved move out of the quick-connect identifier namespace**

- **A profile saved before the previous version stayed in it.** v2026.090401 stopped a new profile
  entering the namespace Heimdall uses for destinations typed into the palette. It changed nothing
  for the profiles already in your file, which load with the identifier they were saved under. Such
  a profile therefore still shared its trust key with a typed destination.
- **Approved certificates move with the profile.** Renaming the profile without moving its
  approvals would have fixed nothing: the approval would have stayed filed under the old
  identifier, the one the palette assigns to a typed destination. The startup migration moves both
  and leaves nothing behind.
- Replacing an existing profile during an import now goes through the same reservation.

### Notes

- What is not addressed, and cannot be: an approval filed under an identifier in that namespace
  **with no matching profile** belongs to a destination someone typed and accepted; removing it
  would re-ask about a machine they already accepted. An approval that belonged to a profile since
  deleted cannot be told apart from it. Both are kept. The situation can no longer arise from this
  version, because no profile can enter the namespace.
- The v2026.090401 notes stated that approval isolation was exact from that version. That was
  premature: the three points above were still open.
