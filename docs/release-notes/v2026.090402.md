### Changes

**Profiles already saved move out of the quick-connect identifier namespace**

- **A profile saved before the previous version stayed in it.** v2026.090401 stopped a new profile
  entering the namespace Heimdall uses for destinations typed into the palette. It changed nothing
  for the profiles already in your file, which load with the identifier they were saved under. Such
  a profile therefore still shared its trust key with a typed destination.
- **Approved certificates move with the profile.** Renaming the profile without moving its
  approvals would have fixed nothing: the approval would have stayed filed under the old
  identifier, the one the palette assigns to a typed destination. The startup migration moves both
  and leaves nothing behind.
- Replacing an existing profile during an import now goes through the same reservation.

### Notes

- What is not addressed, and cannot be: an approval filed under an identifier in that namespace
  **with no matching profile** belongs to a destination someone typed and accepted; removing it
  would re-ask about a machine they already accepted. An approval that belonged to a profile since
  deleted cannot be told apart from it. Both are kept. The situation can no longer arise from this
  version, because no profile can enter the namespace.
- The v2026.090401 notes stated that approval isolation was exact from that version. That was
  premature: the three points above were still open.
