## Francais

### Changements

- **Deux instances de Heimdall ne se marchent plus dessus.** Lancer Heimdall une seconde fois
  ramene la fenetre existante au premier plan au lieu d'ouvrir une deuxieme instance. Auparavant,
  les deux lisaient la configuration au demarrage et la reecrivaient a la fermeture, et la
  derniere ecriture effacait en silence ce que l'autre avait enregistre.
- **Quitter les reglages avec des modifications non enregistrees ne les detruit plus.** La
  question posee etait "Les appliquer avant de partir ?" avec Oui et Non, et Oui les jetait.
  Le dialogue propose maintenant Enregistrer, Abandonner et Annuler, et chacun fait ce qu'il dit.
- **Un champ numerique des reglages refuse desormais une valeur invalide au lieu de l'ignorer.**
  Vider "Sessions integrees max" ou y taper "24h" laissait le reglage inchange sans le moindre
  message, et l'enregistrement annoncait un succes. Vingt et un champs signalent maintenant
  l'erreur, dont le seuil de verrouillage automatique du coffre, ou croire qu'un delai de
  securite est pose alors qu'il ne l'est pas etait le vrai cout du defaut.
- **Un mot de passe enregistre est visible et peut etre supprime.** Les cartes RDP, VNC, FTP,
  WinRM et SSH indiquent qu'un mot de passe est conserve et offrent de le retirer. Un champ vide
  signifiant "conserver", il n'existait aucun moyen d'arreter de stocker un identifiant depuis ce
  dialogue.
- **Enregistrer une session RDP multi-ecrans depuis une machine a un seul ecran ne detruit plus
  la selection de moniteurs.** Les ecrans absents de la machine courante sont conserves.
- **L'avertissement "modifications non enregistrees" ne se declenche plus a chaque visite.**
  Ouvrir une session, ne rien toucher et fermer ne demande plus confirmation.
- **Entree connecte depuis l'arbre des sessions**, comme l'aide F1 l'annoncait deja.
- **Le champ de commande post-connexion est utilisable a la taille par defaut du dialogue.**
- **Les lecteurs d'ecran lisent le contenu des tableaux.** Toutes les grilles du produit
  annoncaient un nom de classe interne a la place de leurs donnees.
- **Une resolution fixe RDP hors bornes est desormais bornee sur la session embarquee**, comme
  elle l'etait deja sur la session externe.

### Pourquoi

Cette version ne vient pas du backlog. Elle vient d'un audit d'experience utilisateur mene sur
l'arbre des sessions, l'onglet General des reglages et le dialogue de session, dont chaque constat
a ensuite ete soumis a une relecture chargee de le refuter plutot que de le confirmer.

Deux des defauts corriges ici detruisaient du travail sans le dire. Les autres faisaient dire a
l'interface quelque chose de faux : un bouton qui annonce appliquer et qui jette, une case qui
semble vide alors qu'un secret est conserve, une aide qui promet un raccourci absent.

### Mise a niveau

Aucune action requise. Les sessions, les reglages et les identifiants existants sont conserves
tels quels.

## English

### Changed

- **Two Heimdall instances no longer overwrite each other.** Launching Heimdall a second time
  brings the existing window forward instead of starting a second instance. Both used to read the
  configuration at startup and write it back on exit, and the later write silently discarded
  whatever the other had saved.
- **Leaving Settings with unsaved changes no longer destroys them.** The prompt asked "Apply them
  before leaving?" with Yes and No, and Yes threw the changes away. It now offers Save, Discard
  and Cancel, and each does what it says.
- **A settings number field now refuses an invalid value instead of ignoring it.** Emptying "Max
  embedded sessions", or typing "24h" into it, left the setting untouched with no message at all
  and Save reported success. Twenty-one fields now report the error, including the vault idle
  auto-lock threshold, where believing a security timeout is set when it is not was the real cost.
- **A saved password is visible and can be removed.** The RDP, VNC, FTP, WinRM and SSH cards now
  say that a password is stored and offer to remove it. Because an empty box means "keep", there
  was no way to stop storing a credential from this dialog.
- **Saving a multi-monitor RDP session from a single-screen machine no longer destroys the
  monitor selection.** Screens absent from the current machine are kept.
- **The unsaved-changes warning no longer fires on every visit.** Opening a session, touching
  nothing and closing no longer asks for confirmation.
- **Enter connects from the session tree**, which the F1 help already said it did.
- **The post-connect command field is usable at the dialog's default size.**
- **Screen readers read table contents.** Every grid in the product announced an internal class
  name instead of its data.
- **An out-of-range RDP fixed resolution is now bounded on the embedded session**, as it already
  was on the external one.

### Why

This release did not come from the backlog. It came from a user-experience audit of the session
tree, the General settings tab and the per-session dialog, where every finding was then handed to
a review whose job was to refute it rather than confirm it.

Two of the defects fixed here destroyed work without saying so. The rest made the interface state
something untrue: a button that says apply and discards, a box that looks empty while a secret is
kept, a help screen promising a shortcut that was never bound.

### Upgrade note

No action is required. Existing sessions, settings and credentials are kept as they are.
