### Changes

**A correction first: what Heimdall does with a server's interactive questions**

The security notes and the troubleshooting guide both said that Heimdall answers only a password
prompt with your stored password, and leaves any other question - a verification code, a challenge -
empty. That was not true, and the truth is the part worth knowing.

When a server asks a single question, Heimdall answers it with the stored password whatever the
question is. Only when a server asks several at once does it pick out the one that reads as a
password request and leave the rest empty. A server whose only question is a verification code
therefore receives your password as the answer to it: the attempt fails, and the server records a
failed second-factor attempt. Second-factor entry is still not supported. This release does not
change that behaviour, it changes the four places that described it wrongly.

**Nothing waits forever any more**

Three separate paths could wait with no limit at all, and each of them held something the
application needed while it waited.

- **A stalled SFTP server no longer freezes the file browser for good.** If a server stopped
  answering while the connection stayed open, the pane waited for it indefinitely and stopped
  responding until you closed it. Each request now has a quarter of an hour. The clock is per
  request, so a download of any size still finishes as long as the link keeps moving; what it
  limits is how slow the link may be, and the floor is about 3.5 KB/s. It makes a wedged pane end,
  not end quickly: freeing itself still takes up to fifteen minutes, and the failure looks like any
  other transfer failure.
- **A privileged file operation no longer hangs forever either.** In sudo mode, creating a folder,
  changing permissions, renaming, deleting and listing each run as one command with no deadline of
  its own, and several of them ran with no way to cancel them at all. Each now carries a ten-minute
  bound. Privileged uploads and downloads deliberately do not: their duration is set by the size of
  the file, and a fixed deadline would abort a legitimate large one.
- **Cancelling an update now takes effect during verification too.** After a download finishes,
  Heimdall reads the whole file back to check it against the published checksum. Cancelling during
  that step used to do nothing until the check had finished.

**An update check that fails now says what stopped it**

"Update check failed. See the log for details." was the answer to five different questions. Being
offline said it, and so did a rate limit, a release page that is not there, an answer Heimdall could
not read, and a connection that could not be secured. Those call for different responses, and the
one thing the message offered was a log most people never find.

The settings page now names the cause, and quotes a waiting time when the server gives one. It does
not guess when the server says nothing, because a waiting time that turns out wrong is worse than
none. One case also changed behaviour: when the update server is refusing requests because too many
have come from your network, Heimdall stops asking at every launch and waits for its ordinary check
interval, since that quota is counted per network address and an office behind one address shares
it. That buys less than it sounds like, and the changelog says exactly how much.

**A replaced release is no longer reported as a corrupted download**

If the maintainer replaces a release between the moment Heimdall checks and the moment you install,
the bytes that arrive are sound and freshly published but no longer match the checksum written down
earlier. Heimdall said "Update verification failed", which is also what it says when a download has
been truncated or tampered with. It now tells the two apart and asks you to check again. A download
matching neither checksum is still reported as a verification failure, because that is what it is.

The newly published checksum is never adopted: installing against whatever the source serves at
install time would give away the only thing writing the checksum down buys.

**Smaller things**

- A release tag Heimdall cannot read no longer reports the update check as failed. There is nothing
  to install, which is a different sentence and a different answer.
- The update relauncher records what it decided, so a failed relaunch can be told apart from one
  that was never attempted.
- The FTPS data-channel warning is now pinned by tests. Nothing about the warning changes for you;
  it can no longer be removed without a test noticing, which matters because the limitation behind
  it cannot be fixed inside Heimdall and the warning is the whole of what Heimdall can offer.
- A login refused because the server asked something Heimdall could not answer is filed under SSH
  authentication in the session diagnostic panel, rather than as a generic failure.
- A server-side copy can no longer be turned into a link to somewhere else, and an interrupted FTP
  replacement no longer leaves an unexplained file behind.
- Cancelling an SFTP connection now reaches the handshake instead of waiting for it to finish.
- The file browser's messages come from the translation catalogue rather than from the code.
