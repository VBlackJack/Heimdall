A first-contact release. Someone who had never seen Heimdall tried it, struggled, and said so.
Everything below came out of walking that path with them rather than reading the code, and most of
it is about gateways and about the first ten minutes.

### Gateways stop lying to you

If you route sessions through a bastion, three separate things were working against you.

**The gateway list told you the wrong reason it was greyed out.** Whenever the list was
unavailable, the help text underneath said gateway selection requires the SSH protocol. That was
wrong twice over: gateways have never been SSH-only, since SFTP, RDP and WinRM all tunnel too, and
if you had ticked "Direct connection" the list was greyed out for that reason and had nothing to do
with the protocol. So anyone who asked why the control was dead was told to change something that
would not have helped. The two causes now have two messages, and each says what to do.

**You can now create a gateway without leaving the session you are configuring.** It is on the
Network tab, next to the list, and the gateway you create is selected immediately.

**A gateway created outside the Settings panel used to vanish.** Adding one from the main Add menu
or from a right-click on empty space put it in a buffer that nothing wrote to disk, so no session
could see it, and the next reload erased it without a word. It is now persisted the moment you
create it.

Two more, found by looking rather than by reading, on the same afternoon the three above shipped:

- A gateway you created while the session dialog was open showed up on the session row as
  **"gateway missing"**, in red, over a gateway that was sitting perfectly intact on disk. Nothing
  was ever lost; the row was resolving the name against a list captured before you created it.
- The same gateway was **absent from Settings** until you restarted. The Settings panel reads its
  gateway list once at startup, and walking to the tab does not count as a reason to read it again.
  It now takes in gateways created elsewhere, and it does so without touching anything you have
  edited there and not yet saved.

### SSH and SFTP settings are no longer one long scroll

The page held SSH clients and mode, anti-idle, auto-reconnect, the SFTP browser, X11, trusted host
keys and gateways, all stacked. It now groups them the way the Remote Desktop page already did:
**Connection, Session, SFTP and X11, Host keys, Gateways.**

Gateways getting its own named tab is the point rather than a side effect. It used to be the last
card of the longest page in Settings, and the person who struggled never found it at all.

### The first five minutes

**The welcome tour used to end by hiding your sessions.** The panel in the middle correctly invited
you to add your first session, while the list that session would appear in had been swapped for the
tools tree. So you added a session and it appeared nowhere you could see. The app remembered that
choice, so the next launch opened the same way. The tour now ends on the session list.

**"Explore Tools" on the welcome panel now opens the tools.** It used to change a narrow strip on
the far left and nothing else, so the panel you had just clicked looked identical and clicking a
second time did nothing at all.

### Clearer failures

- **A rejected SSH password is reported as a rejected password.** When the direct connection fails
  and the PuTTY fallback cannot be found, the message used to name the missing tool and send you
  into Settings, which fixed nothing when the password was simply wrong.
- **A WinRM profile that speaks TLS on the plaintext port is caught before you connect**, and the
  message names both ports rather than leaving you with a timeout.
- **Bulk connect says why servers were skipped**, grouped by reason, instead of giving a count.
- **Importing a configuration writes only what the import changed.** It used to save a whole
  settings snapshot captured when the import started, which quietly undid anything written while
  the file picker was open.

### Accessibility

Item names read by a screen reader now come from a contract rather than from the container type, so
rows no longer announce an internal class name.

### Upgrading

Nothing to do. Settings, sessions and gateways are read as they are.
