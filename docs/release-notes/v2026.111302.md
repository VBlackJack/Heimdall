# Plink terminals start at the full width of their pane

A short release that finishes the work on terminal width started two releases ago. Sessions that go
through Plink could still start narrower than their pane, in two cases found by trying the previous
release on screen. Both are fixed, and three groups of dependencies are updated.

## What you will see

### SSH

- **A Plink terminal in a wide pane starts at the right width.** Since v2026.111201 Heimdall tells
  the terminal the size of its pane while the session is still connecting, because Plink cannot
  change its terminal size afterwards. That estimate was wrong whenever the pane was wider than the
  hidden terminal page itself: the width was capped to that page (1066 pixels on the machine where
  it was measured), so a session in a wide pane started too narrow and showed the "Width fixed"
  badge. A pane narrower than that was right, which is why a tab split in two hid the problem. The
  estimate now follows the pane whatever its width.
- **A session that falls back to Plink no longer starts at half width.** With "Auto-open SFTP panel
  on SSH connection" on, an SSH tab opens split in two before it connects. When the embedded client
  cannot sign in and the connection is retried through Plink (Kerberos, a password typed in the
  "SSH password required" prompt, a refused stored password or key), the SFTP side panel cannot sign in
  either: it uses the same client and the same credentials. Plink was started at the width of the
  split pane, then the panel failed and was removed, and the terminal stayed at half width. The
  pending panel is now withdrawn as soon as the retry starts, and Plink starts at the full width of
  the tab.
- **The status bar says why the SFTP panel is missing.** Once such a session is connected it reads
  "The SFTP panel was not opened: the embedded client could not sign in to this server", instead of
  "SFTP auto-open failed". An SFTP session can still be opened by hand, in its own tab or split beside
  the terminal; with Kerberos it cannot sign in either.
- Sessions that go through Plink because of agent forwarding with Pageant are not changed: their
  SFTP side panel signs in with the agent and stays.

## How this was checked

- On a Windows Server 2022 domain controller running OpenSSH for Windows with Kerberos, at 100%
  display scaling, in a pane 1439 pixels wide. Before: Plink started at 100 columns with the panel
  pending, then at 149 with the panel withdrawn but the cap still there. After: 203 columns, the
  same number the terminal reports once shown, and no badge.
- Not tried: 125% and 150% display scaling, a pane taller than the hidden page, and a refused
  stored password.

## Upgrade notes

- **A tab that connects in the background can still start narrower.** A tab connecting while
  another tab is displayed (bulk connect, sessions restored at startup, switching to another tab
  before the retry starts) or in a minimised window is not laid out again when the SFTP panel is withdrawn.
  It can start at the width of the split and show the "Width fixed" badge. Reconnect it while it is
  displayed to get the full width.
- **Splitting such a tab by hand** (for example with an SFTP session) makes the terminal pane
  narrower than the width Plink started with, so the badge appears. Reconnect to apply the new width.
- **Dependencies updated:** the .NET libraries Heimdall ships move from 10.0.14 to 10.0.15,
  FluentFTP from 54.2.0 to 55.1.0 and LibGit2Sharp from 0.31.0 to 0.32.0. The whole test suite
  passes with them; FTP was not tried against a real server with the new FluentFTP.
