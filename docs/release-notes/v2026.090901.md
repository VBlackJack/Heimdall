# SSH verification-code sign-in

The embedded SSH terminal can now ask for verification codes and other
keyboard-interactive responses after checking the host key. This also supports
a private key followed by a code, or a password followed by a code.

The dialog identifies the server and account and masks the response. The code is
used for that connection attempt only; it is never saved to the profile or vault.
Cancelling the connection closes the dialog. A rejected interactive answer ends
the attempt without an automatic retry through Plink.

This applies to the SSH.NET embedded terminal. SFTP connections, SSH gateway
authentication, gateway diagnostics and sessions using Plink for agent forwarding
retain their existing authentication paths.

## Validation

- Release build and formatting checks passed; all 12,596 local tests passed.
- An isolated OpenSSH/PAM server passed eight checks: correct and incorrect codes,
  user cancellation and token cancellation, with and without a preceding PAM password.
- WPF checks verified response submission, dialog cancellation and clearing the input.
- Two live Windows RDP targets completed four logins with two reused controls. Both
  controls were released after the five-minute idle expiry. The isolated component
  harness measured about 345 MiB while connected, 75 MiB after closing, and 36 MiB
  after expiry. These figures are not a measurement of the full Heimdall application.

RD Gateway, recovery after network loss and redirected-device data transfers were
not exercised in the RDP check.
