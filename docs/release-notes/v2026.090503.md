### Changes

**An idle Remote Desktop control gives its memory back**

- **The pool kept two controls for the life of the process.** The pool that keeps Remote
  Desktop controls alive between sessions, so the next connection does not re-pay a fresh
  control, held two of them until exit. Each holds about 300 MB, so a Heimdall that had been
  used sat about 600 MB above one just started after every tab was closed, and stayed there.
- The pool now reads two settings on the RDP tab, under the Performance sub-tab: how many idle
  controls to keep (0 to 8, default 2) and how many minutes an idle one is kept (default 5;
  0 keeps it until exit, which is what every earlier version did). Both apply without a
  restart. The oldest idle control expires first, a new session takes the most recently
  released one, and the idle controls are released when Heimdall exits.

**The disconnect code is plain ASCII**

- **The code beside the reconnect message used a middle dot between its parts.** It is the
  line people copy from the clipboard report into a ticket, a mail or a console, and the
  middle dot was the only non-ASCII character in that report: a Windows console printed it as
  a question mark, and ticket systems that re-encode a paste turned it into two bytes.
- The separator is now a vertical bar: `RDP_BAD_CREDENTIALS | 2055`, with `| EXT <n>` when an
  extended reason exists. The test that pinned the middle dot now pins the whole code to
  ASCII.

**The drive key in generated .rdp files, measured**

- The audit asked whether the generated `.rdp` file, which carries `redirectdrives` and never
  `drivestoredirect`, still redirects drives on a current Remote Desktop client whose
  documentation lists only the newer key. Measured in the client's own editor: the legacy key
  alone turns drive redirection on, off leaves it off, and the client itself writes the legacy
  key when it saves a file. The file is unchanged.
- The same measurement showed the newer key wins over `redirectdrives:i:0`, so a test now pins
  that the generated file never carries it: adding it unconditionally would redirect drives on
  a profile that said no.

### Notes

- **What was not measured.** The memory returned after an idle control expires was proven with
  an injected clock in tests, not re-measured on a live target; the figures above are from the
  2026-08-24 measurement that motivated the change. The drive key was measured in the client's
  editor, not by listing `\\tsclient` on a target: the two lab targets were offline.
- **Other middle dots stay.** The health tooltip, the palette hints and the post-connect
  progress tooltip keep their on-screen separators; nobody pastes those into a ticket.
- See RDP-PERFORMANCE, section "Memory that is not returned when you close a tab, and for how
  long", and the two Settings FAQ entries on the Remote Desktop control pool.
