# Heimdall asks before it acts as root, and four questions decline by default

This release makes the SFTP browser ask before it runs a refused operation as root, shows what a pane did as
root, hardens the root transfers and permission changes, and makes several questions safer to answer in a
hurry.

## What you will see

### Security

- **Heimdall now asks before it runs a refused operation as root.** When the server refused an upload, a
  download, a new folder, a rename, a permission change, a listing or an edit, the SFTP browser ran it again
  through sudo without a question. It now asks first: the question names the act and the path, and declines
  by default. A transfer, a delete or a permission change of several entries asks once; an editor asks once
  when it opens and says that its saves will also be written as root. A new setting, "SFTP: retry refused
  operations as root" (Settings, SSH & SFTP, SFTP & X11), offers Ask first (the default, for upgraded
  installations too), Automatic (no question) (the earlier behaviour; a delete still asks) and Never. The
  security posture card flags Automatic.
- **An organisation can cap that setting.** A DWORD value `SftpSudoFallbackMax` under
  `HKLM\Software\Policies\Heimdall` (0 Never, 1 Ask, 2 Automatic) limits the choice; the stricter of the two
  applies; Settings disables the looser choices and says the limit is set by your organisation. It is read
  once: a change needs a restart, and a value other than 0, 1 or 2 sets no limit. It is not a security
  boundary: the server's sudo rules remain the real control.
- **Root transfers are hardened.** The scripts that run as root behind the SFTP browser's sudo upload, save,
  download and open-for-edit check more before they act. Nothing changes in use, except the refusal described
  in the upgrade notes.
- **A root permission change in the SFTP browser never follows a symbolic link.** Root now holds the entry
  before it changes it: a folder from inside it, a file through a private root-only folder created beside it.
  A symbolic link, a special file, or an entry that changed in the meantime is refused, and the message says
  which.
- **A wrong sudo password is no longer tried once per file.** In a delete or a permission change of several
  entries, a sudo failure that no later entry can change (password refused, account not allowed, sudo
  missing) stops sudo for the rest of that operation; the other entries are still tried with your own rights,
  and the summary says how many were not tried as root.
- **Four questions now decline by default.** Deleting as root in the SFTP browser, sending a command flagged
  dangerous, broadcasting a command to several terminals, and opening a web console with an external program
  were asked with Yes and No, where Enter answered yes and closing Heimdall during the question counted as a
  yes. Each now names its act, the safe answer is the default, and Escape, the close box and a shutdown all
  decline.
- **Remote file names and broadcast commands hide nothing in these questions.** A file name or a command that holds a
  line break, a right-to-left mark or an invisible character is written with visible codes in these
  questions, so it cannot forge a line or hide a part of itself. What is sent stays exactly what was shown.

### SFTP browser

- **A "root" badge shows what a pane did as root.** From the first operation a pane runs through sudo, a
  badge appears next to the sudo toggle and stays until the pane closes. Its number counts the operations
  attempted as root, failed ones included. Click it, or press Enter on it, for the latest twenty with their
  path, outcome and time. Directory listings as root are counted apart, on one line.
- **The sudo toggle only lists folders as root.** A yes to the question about a folder you cannot open turns
  it on, so the folder and its refreshes are then listed as root without asking again. It never lets a write
  skip the question, and it is disabled when the setting is Never.

### Sessions and questions

- **Declining a question is not an error.** Answering "Do not run" to the question about an imported session
  showed a "Connection Error" window afterwards. It now writes one line in the status bar, and the session
  does not turn to the error state. A group connect counts it as skipped.
- **The emphasised button is the one Enter chooses.** In confirmation windows where the safe answer is the
  default, the accent colour sat on the other button. It now follows the default.
- **The list of commands typed after login now says that only an embedded SSH session types them.** They stay
  listed for every session type, since one approval covers them if the session is later changed to SSH.
- **No ":3389" for a session that has no host.** A local shell or a Citrix session showed ":3389" as its host
  in the import preview. A session type that has no saved-password lookup (local shell, Citrix, Telnet) no
  longer shows the lookup notice, its menu entry, or its status message.

### Names that hold an underscore

- **An underscore in a name or a label is shown.** Menus, buttons, check boxes and lists read the first
  underscore of a text as a keyboard shortcut marker: a bookmark `/etc/my_app.conf` read "/etc/myapp.conf", a
  folder `My_Archive` read "MyArchive", the "snake_case" button read "snakecase". Names that are data (SFTP
  bookmarks, folder targets, tab titles, macro and tool names, recent files) and the labels that hold a real
  underscore are now shown as they are, and a screen reader gets the real text.

### Import

- **An mRemoteNG import creates the empty folders of the file.** A folder that held no session was dropped. It
  is now created, in the order of the file. A file that holds only folders asks before it creates them.

## What to know before you upgrade

- **Questions appear where root used to run silently.** Choose Automatic (no question) in Settings, SSH &
  SFTP, SFTP & X11, to keep the earlier behaviour. A listing the pane starts by itself (opening, following the terminal's folder, the
  refresh after an operation) is not run as root under Ask first: browse to the folder, or turn the sudo
  toggle on.
- **A root permission change now needs GNU coreutils on the server**, as root transfers already did. On
  BusyBox or BSD it is refused instead of run. A sudoers rule that allows only `chmod` no longer matches, since
  the command is a shell script.
- **A root transfer stops with "Transfer failed." where the folder it creates does not come out owned by root
  and closed to other accounts**, for example on NFS with root squashing, or on a CIFS or vfat mount whose
  owner or mode is fixed at mount time. The log gives the reason.
- **A symbolic link is never changed as root.** Browse to its target to change it.
- **Enter no longer confirms the four questions above.** Use the named button, or Tab then Enter.
- **The root badge starts again from zero** when a pane reconnects.

## Verified

- Seen on screen in a test build, against a throwaway server with sudo: the new setting and its default; under
  Ask first, the question for a folder you cannot open (Enter declines, the pane stays where it was) and for a
  new folder (a yes creates it as root, the refresh after it does not ask), and a yes that turns the sudo toggle
  on; under Never, no question and a disabled toggle as soon as the setting is saved; under Automatic, a new
  folder as root without a question and a delete that still asks.
- The root transfers and the root permission change were run as root on Debian 12 and AlmaLinux 9 with the
  commands exactly as Heimdall builds them, and the transfers were refused on Alpine.
- Not tried on screen: the policy cap, uploads, downloads and editors as root, the root badge's list, the
  delete-as-root batch, the dangerous-command and broadcast questions, the web console question, the questions
  about an imported session, the underscore fixes, the mRemoteNG empty folders, French and Spanish for all of
  these.

## Limits that remain

- Symbolic links in the folders that lead to an entry are followed, as before.
- An entry that is a hard link to another file is that file, and the change applies to it.
- The stop after a refused sudo password reads sudo's English messages; on a server whose sudo answers in
  another language the password is still tried once per entry.
