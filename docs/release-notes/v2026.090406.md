### Changes

**The "Route via" list of every network tool follows a gateway edit**

- The sixteen network tools that can tunnel through an SSH gateway built their "Route via" list
  once, from the settings as they stood when the tab was opened, and dialled the entry the user
  picked from that snapshot for as long as the tab stayed open. A gateway edited meanwhile kept its
  old name in the list and its old host, port and credentials on the wire.
- The list now follows the configuration. On a save it is rebuilt from the current gateways and
  the selection is kept by gateway identity, so a renamed gateway keeps its place and an edited one
  is dialled with its new host on the tool's next run. A deleted gateway puts the tool back on a
  direct connection and says so on the tool's own error line.
- A save that does not touch the selected gateway leaves the tool alone. Two of these tools answer
  a gateway change by probing the remote subnet over SSH, and would otherwise have probed on every
  unrelated save.
- v2026.090405 said in its notes: "The Route via selectors inside the network tools still list the
  gateways as they were when the tool tab was opened. Reopen the tab after editing a gateway."
  That sentence is no longer true. Reopening the tab is not needed.

**A tool opened into a split pane lists the gateways**

- Splitting a session with a network tool opened that tool without the settings, so its "Route via"
  list held "Direct connection" and nothing else, whatever the settings said. A split pane now
  lists the same gateways as a tab and follows the same edits.

**The SecNumCloud audit keeps the host it was opened with**

- Opening the SecNumCloud audit from a server filled the scope with that server, then replaced it
  with the local subnet a moment later. The replacement came from the "Route via" list's own
  selection event at initialisation, which is no longer raised. The scope stays on the server.

### Notes

- A run already in progress keeps the tunnel it opened. Every tool, the network cartography
  included, reads the gateway once when the run starts and holds it for the run; the edited gateway
  is dialled by the next run, not the current one.
- Renaming a gateway still keeps the old name on an open connection's tab, in the Tunnels panel and
  on a certificate question, as v2026.090405 said: that records what happened. See the Settings FAQ,
  section "SSH gateways, PuTTY and Plink".
