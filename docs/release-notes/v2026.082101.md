This release is mostly about things the application did quietly and wrongly. Four of them changed or
discarded your data without saying so, and one let a security setting be bypassed from a menu.

### Editing a server no longer deletes parts of it

The server dialog builds a fresh profile and the caller writes it over the stored record, so any
field the dialog does not show was replaced by its default on every edit. Four were being lost.

The worst was the Citrix launch command line, which is what the launcher reads in order to start a
published application at all: renaming a Citrix profile broke its ability to connect. A profile also
lost its position in the gateway overview, its tunnels panel state, and any setting written by a newer
version of Heimdall.

### Local shells no longer lose their elevation when you save their settings

A profile stores elevation twice, in the current mode and in a legacy flag that predates it. The
launcher reconciles the two; the dialog read the raw value and showed None for a profile that does in
fact elevate. Opening such a shell's settings and pressing Save, changing nothing else, took its
elevation away. Saving now also settles the profile onto the current field, so it stops depending on
the legacy flag.

### Connecting a whole folder now asks for Windows Hello

Right-clicking a folder and choosing Connect all resolved and used stored credentials without the
Windows Hello verification, even with the setting turned on. The gate was applied at the two entry
points that path did not use. It now lives in the single place every bulk connection passes through,
immediately above the credential resolution it protects, so no caller can arrive past it.

Connecting a single server was never affected.

### Two settings no longer refuse to save in silence

Saving is refused when any setting is out of range, but the warning banner and the per-tab error
badges were counted from a separate list, and two settings were on neither: the update check interval
and the RDP keep-alive interval. Entering a bad value in either refused the save with no banner, no
badge and no field error, so pressing Save simply did nothing.

Four further settings were counted on the Advanced badge although their fields are on the RDP tab,
which sent you to the wrong tab to find the field at fault. The RDP tab now has its own badge.

### The RDP connect watchdog can be turned off again

Zero disables it, which the watchdog itself and the settings schema both accept, but the settings
screen rejected it. A configuration with the watchdog disabled opened with an error on a field that
was set correctly, and blocked saving anything else on that screen until it was changed.

### Remote Desktop disconnects say more, and say it once

Sessions going through a Remote Desktop Gateway used to end with "unknown disconnect code". The
gateway and RemoteApp families are now recognised, six gateway causes are named individually, and six
further common causes have messages: account disabled, logon-hours restriction, Network Level
Authentication required, no reachable authentication authority, expired certificate, and clock skew.

Codes whose meaning is not established stay unnamed on purpose. An invented label is worse than
saying the code is unknown.

Alongside the message, the overlay used to print a symbolic cause derived from a different code than
the message itself, so a gateway timeout was labelled as a socket close. Both now come from one
resolution, and both numbers are shown.

### A dropped session behaves the same whichever code reports it

The client reports a failed reconnection under either of two codes and shows one message for both,
but only one of them allowed the automatic retry to continue. The same drop therefore either kept
reconnecting under a blue notice or was torn down on the first bounce under a red error, beneath a
word-for-word identical sentence. They are now treated alike.

A failed reconnection also no longer pre-selects "Edit profile" on the overlay. That was decided when
the code was believed to mean a display-resolution timeout; nothing in the profile is at fault for a
reconnection that failed.

### Cancelling a reconnection no longer looks like starting one

Clicking Cancel put the view into the phase that means a connection is being prepared, so the phase
stepper lit its first segment, a second button with the same Cancel label appeared where the first
had been, and the connect watchdog was armed. The status line said the session was closing while
everything around it said one was starting.

### Under the surface

Five tests were rewritten because they could pass without testing what they claimed. Two could report
success having replayed nothing; one asserted a wall-clock bound that a loaded machine could exceed
for reasons unrelated to the defect; one failed a passing test because a temporary file could not be
deleted while the process that had just been started still held it. None of these changed how
Heimdall behaves, and all of them change what a green test run is worth.
