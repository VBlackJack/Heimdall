# New files upload again over FTP and restricted SFTP, and a WinRM tab that stays remote

This release repairs three things that could stop your work or put it in the wrong
place: uploading a new file over FTP, FTPS or a restricted SFTP account, a failed
WinRM session that left a PowerShell prompt on your own machine, and the way SSH
answers a server that asks for a second factor. It also closes four places where a
password or a file could reach someone it should not, and goes over the session
tree and the Settings panel from end to end.

## Uploading a new file works again over FTP, FTPS and restricted SFTP accounts

Since v2026.090801, every upload of a file that did not exist yet on an FTP or FTPS
server was refused with "The upload could not be confirmed without replacing a
file". FTP uploads it again. Just before moving it into place, Heimdall checks that
the name is still free, and refuses rather than replace a file that appeared in the
meantime. A file created in the instant between that check and the move can still be
overwritten: FTP has no command that would prevent it.

On SFTP, a new file was published by a command run over an extra SSH connection. That
failed on accounts restricted to SFTP (`internal-sftp` in a chroot), on Windows
OpenSSH and behind SFTP gateways, and cost one more connection per file everywhere
else. It is now published by the SFTP protocol's own rename, which refuses a name that
already exists, so a file that appeared since the listing is reported as a collision
and never replaced.

## A failed WinRM session no longer leaves you at a local prompt

When the sign-in failed, the remote session ended or the connection dropped,
PowerShell fell back to a prompt on this computer, inside a tab still named after the
remote host. Broadcast, the Command Library and macros then ran their commands on your
own machine. The session now ends instead: the error stays on screen and the tab
shows the session as ended. Under Constrained Language Mode this cannot apply, and
PowerShell behaves as before.

The messages around a WinRM launch say what actually happened. The explanation of
the NTLM loopback and WSMan 12152 errors appears again. A sign-in script refused by an
execution policy your organization enforces is explained, with two ways out: the
current Windows identity for that host, or your administrator. A locked vault, an
unreadable stored password and a terminal that cannot start each have their own
message.

## SSH: a second factor no longer receives your password

A server that asks for a one-time code (one-time, OTP, verification code, token,
passcode, and their French, German and Spanish forms) used to be sent your stored
password when that was its only question, or whenever its wording contained the word
"password", as "One-time password (OATH)" does. Each such answer spent one of the
code's attempts. The question is now asked of you in the SSH terminal, and left
unanswered where nobody can be asked: the file browser, gateways and the route test.
Once a server has accepted the password as a first factor, it is not sent a second
time.

Pressing Cancel in the verification-code dialog now reads as a cancellation, instead
of "SSH authentication timed out after 20 seconds" with advice about Pageant, and no
second attempt is started behind it.

An embedded SSH session to a host that does not answer gives up after 15 seconds
again, like every other connection. It had been waiting two minutes, the time meant
for typing a code.

## Security hardening

- **RDP with Network Level Authentication off no longer hands the password to mstsc.**
  In External or Force-External mode with NLA off, mstsc does not check the server's
  identity, so supplying the password meant signing in to whatever answered at that
  name. mstsc now asks you for it, and a notice says why. With NLA on nothing changes.
- **A second external RDP launch to the same host with another account is refused**
  while the first is still starting. It used to open the session as the first account.
  You are asked to retry in a few seconds. Launching the same account twice is
  unaffected.
- **A copy made on an SFTP server stays private while it is written.** The temporary
  copy was readable by every user of that server until the copy finished. It is now
  readable by your account only, until the source's permissions are applied.
- **A question from an SSH server is presented as the server's.** The dialog names the
  server, quotes its text, and says that Heimdall never asks for its master password
  there. Line breaks, invisible characters and text-direction overrides are removed,
  and the text is cut at 256 characters, so a server can no longer lay out a question
  that reads as if Heimdall had written it.
- **The encrypted WinRM password is kept out of the PowerShell event log**, where
  script-block logging used to record it inside the sign-in script.
- **Imported WinRM profiles no longer skip the certificate check.** "Skip certificate
  validation" is cleared on every imported profile; turn it back on if you need it.
- **The external editor refuses a working folder it cannot protect**, rather than
  staging a file, a root-owned one included, where other users of the computer could
  read it.

## The session tree: a search that finds what you type

- **Search matches every word you type, wherever it is.** "web prod" now finds web01
  filed in the Prod folder. Each word is looked up in the name, address, folder,
  username, protocol, environment, tags and project, and accents are ignored.
- **The search box answers Escape, Down and Enter.** Escape clears it, Down moves to the
  first session, and Enter opens the session when exactly one matches.
- **The selection comes back.** A search or a closed folder that hid the selected
  session no longer clears it for good: it is restored once its rows show again.
  Right-clicking one of several selected sessions keeps them all selected.
- **Favorites from the tree.** The context menu adds or removes a favorite, for one
  session or a selection, and a favorite row shows a small star.
- **Move menus nest like the folder tree** instead of listing every folder as one flat
  list of paths.
- **Rows stay still.** The selection count, the selection actions and the undo bar now
  sit below the tree, where they no longer push the rows down between two clicks. The
  undo bar names what it undoes and withdraws after 30 seconds.
- **Status reads by shape as well as colour**, and the dots keep their state when the
  tree reloads. Long names end in an ellipsis, and counts have a singular and a plural.

## Settings: Save is the rule, and the panel says when it is not

- **Save is offered only when there is something to save**, and "Settings saved"
  appears after a save. Each section says when its settings take effect, and which
  ones are saved immediately, outside Save.
- **Turning TFTP sharing on waits for Save, and asks first.** It used to start serving
  files on the spot, and Undo changes could not take it back. Turning session
  transcripts on asks in the same way, and warns that transcripts keep what you type.
- **Apply to all saved sessions keeps your other edits** instead of throwing them
  away, and says how many sessions will change.
- **Export and import your preferences.** A "Settings file" card on General writes the
  settings the panel edits to a file that never holds a secret, and an import shows
  what would change, then leaves it pending until you save.
- **Reset defaults keeps your language, theme and security enrolment.**
- **The settings search finds, shows and counts what it matches**, opening the tab and
  section that hold it. Ctrl+F on the Settings tab goes to it.
- **A refused Save says which field is wrong**, marks it, and moves focus to it.
- **A Save in Settings no longer erases a project** added meanwhile from the tree.
- **Accessibility.** Every input has a name, Tab reaches a field before its buttons,
  French and Spanish labels are no longer cut off, and status lines are announced.

## Also

- Uploads the server refuses from the external editor are reported once, with the
  reason, instead of retried every two seconds.
- Browse as root lists a linked folder, and shows owners and groups by name again.
- Connecting in sudo mode can be cancelled, and privileged commands no longer wait
  forever.
- A failed folder copy on SFTP never deletes a folder it did not create, and a copy can
  no longer land inside a folder by accident.
- Test route for SSH gateways gives each hop 15 seconds, as the tunnel does, and
  reports a destination the gateway cannot reach as a failure.
- One copy of Heimdall no longer resets the terminal size of another running copy.
- An approved RDP certificate is written before Heimdall exits, and creating a folder
  or saving a scheduled task can no longer bring back a certificate you revoked.
- Two split panes sharing one gateway tunnel no longer lose it when one of them fails
  to reconnect.
- Editing the username of several sessions at once no longer switches WinRM profiles
  to a stored credential they do not have.
- Resolution presets are checked instead of trimmed as you type, Test connection for
  Git sync tests what you typed, tool paths say when nothing is there, and four
  settings that only the settings file could change are now on screen.
