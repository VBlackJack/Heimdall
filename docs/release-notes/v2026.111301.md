# Kerberos sign-in through Plink, the bundled Plink first, and terminals that keep their first lines

A release of fixes for SSH sessions that go through Plink, found while following up the previous
release and a user report (GitHub discussion 500). The main ones: a session that signs in with
Kerberos no longer has to type a dummy password, Heimdall uses the Plink it ships instead of the one
installed with PuTTY, and the banner and the first prompt are no longer lost.

## What you will see

### SSH

- **Kerberos signs in without a password.** When a session has a user name, no stored password and
  no key file, and the connection goes through Plink, the "SSH password required" prompt now says:
  leave it empty to sign in with Kerberos (your Windows sign-in) or a key held by Pageant. With an
  empty answer Plink is started without a password; no password file is written and no password is
  sent. Before, an empty answer cancelled the connection, so a Kerberos user had to type any text
  to get through. Cancel still cancels, and a typed or stored password works as before.
- **A refused sign-in is explained instead of leaving a blank terminal.** An empty answer starts
  Plink in batch mode, so when the server refuses the sign-in Plink exits at once instead of
  waiting for ever on a prompt shown nowhere. The terminal and the disconnected panel then say that
  the connection was started without a password and what to do: connect again and type the
  password, or store it in the session.
- **Heimdall uses the Plink it ships.** The "Path to plink.exe" setting defaults to
  `C:\Program Files\PuTTY\plink.exe`, and that file was used whenever PuTTY was installed there.
  The default value now means the bundled Plink (the PuTTY file is used only if the bundled copy is
  missing); a path you chose yourself is still used as it is. This applies to SSH sessions, gateway
  tunnels and the host key check that go through Plink. On a machine with PuTTY installed, a
  session with a chosen agent key that goes through Plink is no longer refused because the Plink in
  use was not the one shipped with Heimdall. The settings screen no longer reports the default
  value as a missing file, and the hint under the field says what the default value means.
- **The banner and the first prompt are no longer lost with the bundled Plink.** Two parts of
  Heimdall that clean up after Plink starts (one deletes the temporary password file, the other the
  temporary saved session that carries the terminal size) listened to the output before the
  terminal did and received its first lines, so the terminal opened without its banner and first
  prompt. They now listen to a separate signal, and the terminal gets everything.
- **The temporary password file is also deleted when the tab is closed** before Plink has read it,
  not only when Plink reads it or exits.

### Terminals

- **Telnet keeps its first lines too.** Output a Telnet device sends before the terminal is ready
  is now kept and shown, as SSH sessions have done since the previous release and local terminals
  already did. A device that prints a message and closes at once now shows that message and the
  end of the session, instead of a tab that looked connected. This was checked on scripted streams,
  not on screen and not on a real Telnet device.
- **Each installation has its own browser profile folder for its embedded pages** (terminal, VNC,
  diagram and Markdown editors). Two Heimdall installations, or two versions side by side, shared
  one folder. A first terminal that took minutes to appear was seen once, and this sharing is the
  suspected cause. The folders of previous versions (`SSH`, `VNC`, `DrawIO`, `MilkdownEditor`
  directly under `%TEMP%\Heimdall\WebView2`) are left in place and can be deleted once no older
  version is running.

## How this was checked

- Kerberos: on a Windows Server 2022 domain controller running OpenSSH for Windows with GSSAPI,
  with Heimdall on the same machine. The bundled Plink signed in without a password, an empty
  answer connected, and a refused user got the explanation in the disconnected panel. It was not
  tried against a Linux server, with delegation, or through a gateway.
- The blank terminal: with the bundled Plink against an OpenSSH server that refuses the sign-in,
  with and without batch mode.

## Upgrade notes

- **An empty answer to the Plink password prompt no longer cancels.** It starts the connection
  without a password, for Kerberos or a Pageant key. Use Cancel to cancel.
- **A second factor asked after Kerberos is not supported with an empty answer:** Plink runs in
  batch mode and cannot answer it. Typing the password instead was not tried.
- **A PuTTY variant installed at the default path is no longer used while the bundled Plink is
  present.** If you rely on a build of PuTTY installed in `C:\Program Files\PuTTY` (a smart card
  build for example), copy it to another folder and point "Path to plink.exe" to that copy. A path
  that differs from the default is used as before.
- **In external PuTTY mode the host key is now checked with the bundled Plink,** while the window
  is still the PuTTY installed on the machine.
- **The SFTP side panel does not sign in with Kerberos.** On a Kerberos-only server the tab opens
  split, the panel does not connect and is removed, and the terminal keeps the width it started
  with: the "Width fixed" badge says so. This is not fixed in this release. Turning off "Auto-open
  SFTP panel on SSH connection" opens these sessions at full width.
