# Des sessions partagées utilisables par une équipe dès le premier jour, une bibliothèque de commandes dans votre langue avec des runbooks, et une copie du terminal qui garde ses secrets

Cette version rend un fichier MobaXterm partagé utilisable par toute une équipe le jour où il est
ajouté : cinq types de session sont chargés, chaque session qui ne l'est pas est listée avec sa
raison, et les mots de passe de chacun sont mémorisés sur son propre ordinateur. La Command Library
est réécrite en anglais avec son français à côté, connaît la session depuis laquelle elle a été
ouverte, capture une commande depuis le terminal et enchaîne des étapes en runbooks. Et toute
session de terminal peut copier ce qu'elle a affiché avec ses secrets masqués.

## Sessions MobaXterm partagées

- **Cinq types de session.** SSH et RDP étaient déjà chargés ; les sessions Telnet, VNC et SFTP le
  sont désormais aussi. L'import MobaXterm ponctuel des Paramètres les reprend également.
- **Chaque session ignorée dit pourquoi.** FTP (envoie le mot de passe en clair, pas encore
  importé), WSL (un système Linux de l'ordinateur MobaXterm, rien à joindre), les autres types, et
  les sessions dont Heimdall ne peut pas suivre la route : une session Telnet ou VNC passant par un
  rebond SSH, une session SSH, Telnet, VNC ou SFTP passant par un proxy, et une session RDP qui
  s'authentifie auprès de sa passerelle RD Gateway par carte à puce. Chacune est listée dans le
  rapport d'import et dans le résumé d'import des Paramètres avec sa raison, au lieu d'être chargée
  comme une connexion directe qui contournerait le bastion, le proxy ou la passerelle.
- **La passerelle RD Gateway est reprise.** Une session RDP réglée pour toujours passer par sa
  passerelle RD Gateway et qui s'y authentifie par mot de passe garde cette passerelle : Heimdall se
  connecte à travers elle. L'identifiant de passerelle n'est pas repris. Une session réglée sur
  Never ou Detect se connecte en direct, comme dans MobaXterm.
- **Les mots de passe SFTP mémorisés par utilisateur**, comme les mots de passe SSH : la même case
  "Mémoriser ce mot de passe sur cet ordinateur", les mêmes règles, et oublié quand le serveur le
  refuse.
- **Les mots de passe VNC saisis et mémorisés.** Une session VNC partagée dont le serveur demande
  un mot de passe était une impasse. La session attend désormais sur "Ce serveur VNC demande un mot
  de passe" et propose **Saisir le mot de passe**, avec la même case Mémoriser. La connexion reste
  ouverte pendant la saisie, pour qu'un serveur comme TigerVNC ne compte pas un échec de connexion
  et ne bloque pas votre adresse. Un mot de passe refusé est oublié et la question proposée à
  nouveau. Un seul bandeau porte le message, là où deux se superposaient.
- **Rapport d'import.** Les doublons d'hôtes comparent l'hôte et le protocole : une session SSH et
  une session RDP vers un même hôte sont deux façons de l'utiliser, pas des doublons. Les sessions
  hors passerelle ne comptent que les types de session qui peuvent nommer un rebond dans MobaXterm.
- **Les limites sont écrites** dans le guide : une session RDP partagée demande son mot de passe
  dans l'invite Sécurité Windows et Heimdall ne le mémorise pas (rangez-le dans le fournisseur
  d'identifiants externe sous le nom d'hôte) ; les outils réseau passent par vos propres
  passerelles, pas par un bastion partagé ; le dossier de départ distant d'une session SFTP n'est
  pas repris ; une session Telnet demande son identifiant dans le terminal ; un serveur VNC qui
  demande aussi un nom d'utilisateur reste hors de portée.

## Command Library

- **Le catalogue dans votre langue.** Les actions livrées et leurs catégories s'affichent dans la
  langue de l'interface, et un changement de langue recharge la bibliothèque en gardant l'action
  sélectionnée. Le catalogue est rédigé en anglais avec son français à côté ; l'espagnol affiche
  le texte anglais pour l'instant. Les catégories sont des clés stables en interne : la recherche
  trouve une action par le libellé localisé de sa catégorie, et un export pris avant cette version
  s'importe dans les catégories actuelles.
- **Un catalogue qui suit la version installée.** Quand une mise à jour modifie les actions
  livrées, elles sont remplacées au lancement suivant ; vos propres actions, ainsi que les favoris
  et l'historique des actions toujours livrées, sont conservés. Dix actions quasi identiques ont
  été fusionnées en une seule chacune (lsblk, curl -I, du -sh, chown, chmod, traceroute, dig) : un
  favori sur l'un des dix identifiants retirés est perdu.
- **527 actions livrées, Linux et Windows.** 95 nouvelles actions comblent les manques : côté
  Linux, nginx et Apache, les clés SSH, les comptes et leur expiration, firewalld, nftables et
  ufw, NetworkManager, l'heure et le nom d'hôte, les modules du noyau et sysctl, le swap, SMART,
  mdadm, LUKS, les partages NFS et SMB, realm, SSSD et LDAP, auditd, SELinux et AppArmor, OpenSSL
  et certbot, libvirt et kubectl ; côté Windows, WinRM, les correctifs, les connexions TCP, la
  configuration IP et le pare-feu, DHCP, DFS, les clusters de basculement, les clichés
  instantanés, les disques et SMB, le registre, CIM, les niveaux d'événements et l'impression. Les
  commandes qui exigent root commencent par `sudo`, les paramètres d'options sont devenus des
  choix, chaque valeur par défaut livrée génère (quatre ne le faisaient pas), et les exemples qui
  ne correspondaient pas à leur action ont disparu.
- **Pack d'allègement pour poste de travail.** Les 72 actions qui épurent un poste Windows
  personnel (applications du Store, Edge, OneDrive, télémétrie) sont livrées à part du catalogue,
  dans `data\packs\windows-workstation-debloat.json` du dossier d'installation. Importez ce fichier
  avec le bouton Importer de la bibliothèque si vous les voulez. Elles visent un poste de travail,
  pas un serveur ; leur texte est pour l'instant en français seulement.
- **La bibliothèque connaît la session depuis laquelle elle a été ouverte.** Le filtre de
  plateforme démarre sur celle de la session, un paramètre d'hôte est prérempli avec l'hôte de la
  session et un paramètre d'utilisateur avec son nom d'utilisateur, et chaque ligne montre sa
  commande sous son titre. Un profil peut déclarer le système d'exploitation de sa machine
  distante (onglet Général, **Système d'exploitation distant**) : Windows ou Linux est pris tel
  quel, et Automatique garde la déduction tirée du protocole, si bien qu'une connexion SSH vers un
  serveur Windows OpenSSH reçoit le modèle Windows. Les étapes post-connexion suivent la même
  déclaration.
- **Insérer** (Maj+Entrée), entre Copier et Envoyer, tape la commande à l'invite du terminal sans
  l'exécuter, pour que vous puissiez la relire, la modifier et appuyer vous-même sur Entrée. La
  confirmation des commandes dangereuses n'est jamais demandée, puisque rien ne s'exécute.
- **L'historique sait où une commande est partie.** Chaque entrée enregistre l'hôte de la session
  et si la commande a été envoyée ou seulement copiée ; une case **Cet hôte uniquement**, cochée
  quand la bibliothèque appartient à une session, ne montre que ce qui est parti vers cet hôte.
  Envoyée signifie que le texte a atteint le terminal, pas qu'il a réussi : un terminal ne renvoie
  rien, aucun code de sortie n'est donc enregistré.
- **Capturer une commande depuis le terminal.** Sélectionnez une commande dans une session SSH,
  Telnet, WinRM ou shell local et appuyez sur **Ctrl+Maj+L**, ou faites Maj+clic droit et
  choisissez **Enregistrer la sélection dans la bibliothèque de commandes**. L'éditeur d'une
  nouvelle action s'ouvre, dans l'onglet de bibliothèque déjà ouvert s'il y en a un, avec la
  commande dans le motif de la plateforme de la session, le risque à Run, le protocole comme tag
  et le titre laissé à vous. Une sélection sur plusieurs lignes devient une seule ligne, reliée
  par `;` pour Windows et `&&` pour Linux, à relire avant d'enregistrer. Un clic droit simple
  colle toujours.
- **Runbooks.** Un runbook enchaîne les étapes que vous enverriez sinon une à une à chaque
  incident, par exemple état, journaux, redémarrage, état. Le bouton **Runbooks** de l'en-tête de
  la bibliothèque liste les vôtres, avec Nouveau, Modifier, Dupliquer, Supprimer et Exécuter. Une
  étape est une action de la bibliothèque avec une valeur par paramètre, ou une commande saisie
  telle quelle pour une plateforme ; une valeur écrite `{{nom}}` prend une variable que
  l'exécution demande une fois au début, préremplie avec l'hôte et l'utilisateur de la session.
  L'exécution est manuelle, étape par étape : le panneau montre chaque étape avec son état et la
  commande en cours, avec **Envoyer au terminal**, **Insérer**, **Copier**, **Passer** et
  **Arrêter**. Un terminal ne renvoie aucun code de sortie : vous lisez la sortie, puis envoyez
  l'étape suivante ou arrêtez. Envoyer demande la confirmation des commandes dangereuses pour une
  action dangereuse et toujours pour une étape littérale. Les runbooks sont vos propres données :
  aucun n'est livré avec Heimdall, et l'export, l'import et la synchronisation Git les
  transportent avec vos actions.
- **L'export demande quoi inclure** : **Mes actions** (par défaut : ce que vous avez créé ou
  importé, et vos runbooks), **Filtre actuel** ou **Tout**, catalogue fourni compris.
- **La synchronisation Git** ne refuse plus une action marquée Run ou Dangerous, et un modèle avec
  un paramètre de type choix, nombre ou lettre de lecteur survit désormais à un aller-retour.
- **Moins de refus à tort.** Une valeur placée entre apostrophes simples peut contenir des
  caractères du shell (un filtre LDAP, par exemple) : le générateur ne les refuse que là où les
  apostrophes ne protègent pas. Un chemin est jugé sur sa forme, pas sur l'endroit qu'il désigne.
  Tous les messages que le générateur peut afficher sont traduits, les deux qui n'existaient
  qu'en anglais compris, et un paramètre de type inconnu est tout de même contrôlé contre les
  caractères de contrôle.
- **Des commandes générées plus propres.** Un paramètre optionnel laissé vide est omis de la
  commande au lieu de devenir un argument vide `''` (`hostname ''` devient `hostname`), et une
  valeur qui ne contient rien que le shell pourrait interpréter (un port, un chemin, un nom
  d'unité) est insérée nue plutôt qu'entre apostrophes : `--add-port='8080'/'tcp'` se lit
  `--add-port=8080/tcp`. Les motifs peuvent faire 4000 caractères, les commandes 4096 et les
  valeurs 1024 : les neuf scripts du pack d'allègement qui s'ouvraient sur une erreur de
  longueur se génèrent désormais.
- **La synchronisation Git dit ce qu'elle a gardé.** Après une synchronisation, la bibliothèque
  indique combien d'actions ont été gardées en local parce qu'elles étaient plus récentes que la
  copie distante, avec leurs titres dans une infobulle et dans le résumé ; les messages de la
  synchronisation elle-même ("Pull completed", "Sync complete" et les autres) s'affichent dans
  la langue de l'interface ; et un runbook seulement exécuté, ou importé, ne passe plus pour une
  modification locale à la synchronisation suivante. Le nom et l'adresse de l'auteur Git dans les
  réglages sont préremplis depuis votre configuration Git globale tant qu'ils portent encore la
  valeur livrée.
- **Petites choses.** Ajouter ou dupliquer une action la sélectionne, et la sélection survit à un
  rechargement. Les titres des étapes post-connexion s'affichent dans la langue de l'interface.
  L'éditeur propose les types de paramètre nombre et lettre de lecteur. Les lignes du sélecteur
  d'action tiennent dans leur fenêtre et portent un nom pour les lecteurs d'écran, et l'en-tête
  d'exécution ne tronque plus son statut.

## Copier la sortie, secrets masqués

- **Ctrl+Shift+M** dans un onglet SSH, Telnet, WinRM ou shell local, le menu de l'onglet de
  session, ou la palette Ctrl+K. Heimdall lit le texte de la session (les 4 derniers Mio), masque
  les secrets qu'il reconnaît (clés privées, en-têtes d'autorisation, identifiants dans une URL,
  secrets clé-valeur comme `DB_PASSWORD=`, mots de passe en ligne de commande, jetons AWS, GitHub
  et Slack, JWT, invites de mot de passe affichées) en `[masked:<règle>]`, et montre un aperçu avec
  le compte par règle et une option qui remplace les noms d'hôtes et les adresses IPv4 par des
  pseudonymes stables. Rien n'atteint le presse-papiers tant que vous n'appuyez pas sur
  **Copier**.
- Tout se passe sur la machine, sans réseau et sans rien écrire sur le disque. Si une règle dépasse
  son délai, rien n'est copié. La commande est absente des onglets RDP, VNC, SFTP et web, et le
  raccourci n'atteint jamais un bureau RDP. Les journaux de session ne sont pas masqués.
- Les règles sont des motifs : elles manquent ce qu'elles ne décrivent pas (noms d'utilisateurs,
  chemins, un mot de passe tapé sans invite qui le précède). Relisez l'aperçu avant de coller.

## Serveur de fichiers rapide

- **Les liens restent dans le dossier partagé.** Un lien symbolique ou une jonction placé dans le
  dossier partagé menait en dehors. HTTP répond désormais 403 et TFTP "File not found" pour un
  chemin qui passe par un lien, et la liste du dossier omet les liens. Les fichiers OneDrive à la
  demande et les fichiers dédupliqués sont toujours servis.
- **Plusieurs téléchargements à la fois.** Les requêtes HTTP étaient servies une par une, si bien
  qu'un téléchargement lent retenait toutes les autres. Jusqu'à huit sont servies en même temps ;
  les autres attendent dans la file, et aucune n'est rejetée.
- L'entrée 33 du dépannage dit que HTTP sans élévation n'écoute qu'en local, et donne la commande
  `netsh http add urlacl` qui l'ouvre au réseau.

## Corrections

  les compteurs finaux, qui pouvaient afficher 1 sur 2 après une exécution terminée.
