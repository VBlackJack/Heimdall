# Une mise à jour ne laisse plus Heimdall fermé à cause d'une apostrophe, et Windows PowerShell garde ses propres modules

Une petite version de correctifs. Une mise à jour pouvait ne pas relancer Heimdall
quand un chemin contenait une apostrophe typographique, et le Windows PowerShell que
Heimdall démarre pour les mises à jour et les actions sur les services pouvait charger
les modules de PowerShell 7.

## Une mise à jour ne laisse plus Heimdall fermé à cause d'une apostrophe

PowerShell termine une chaîne entre apostrophes sur une apostrophe typographique, comme
en produisent certains claviers et la correction automatique, tout comme sur une
apostrophe droite, et Heimdall n'échappait que l'apostrophe droite. Un profil Windows
nommé comme O'Brien mais saisi avec une apostrophe typographique empêchait le relanceur
de mise à jour de démarrer, ce qui laissait Heimdall fermé après une mise à jour.

Chaque sorte d'apostrophe est désormais échappée, dans le relanceur de mise à jour et
partout où Heimdall construit une commande PowerShell à partir d'un chemin ou d'un nom :

- Démarrer, Arrêter et Redémarrer dans le Tableau de bord des services.
- Le lancement WinRM.
- La commande cd PowerShell envoyée depuis un chemin de fichier.
- Les commandes Windows générées depuis la bibliothèque de commandes.

## Windows PowerShell utilise ses propres modules quand Heimdall part de PowerShell 7

Quand Heimdall était démarré depuis une session PowerShell 7, le Windows PowerShell
qu'il démarre héritait des dossiers de modules de PowerShell 7 et utilisait les modules
de PowerShell 7, une combinaison qu'aucun des deux PowerShell ne prend en charge.

- **Mises à jour.** Le Windows PowerShell qui installe une mise à jour reçoit
  maintenant le chemin de modules hérité sans les entrées de PowerShell 7, toutes les
  autres entrées conservées, comme le fait déjà l'onglet WinRM. Les vérifications de
  signature et de SHA-256 de l'installeur s'exécutaient dans les deux cas.
- **Tableau de bord des services.** La liste des services utilise le même
  chemin de modules.
- **Démarrer, Arrêter et Redémarrer un service.** Ces actions s'exécutent dans un
  Windows PowerShell élevé, qui chargeait le module Management de PowerShell 7 pour la
  commande de service. Son script fixe maintenant le même chemin de modules avant toute
  autre chose.
