# Les variables MobaXterm manquantes, nommées et à un clic

Une petite version qui suit v2026.110501. Quand les sessions d'une source partagée utilisent une
variable MobaXterm qui n'a pas de valeur sur votre poste, Heimdall la signale maintenant une fois au
lieu d'une fois par session, et la page des paramètres nomme la variable avec un bouton qui l'ajoute.

## Ce que vous verrez

### Sessions partagées : le rapport d'import

- **Un constat par variable manquante.** Une variable comme `[DAS]` sans valeur donnait un constat
  par session qui l'utilise, 79 lignes pour 79 sessions. Le rapport affiche maintenant un seul
  avertissement par variable et par source : "[DAS] n'a pas de valeur dans les variables d'import
  MobaXterm : 79 sessions chargées avec le jeton tel qu'écrit." Le nombre affiché sur la source
  compte les variables, pas les sessions.
- **Copier et Exporter en CSV listent toujours chaque session.** Copier les liste sous le constat ;
  le CSV donne une ligne par session, un tableur peut donc toujours filtrer par dossier.
- **Une passerelle comme `[DAS]@bastion` reste sur une seule ligne** dans la fenêtre du rapport ; la
  phrase se replie autour.

### Paramètres : variables d'import MobaXterm

- **La carte nomme les variables dont vos sources partagées ont besoin.** "Utilisées par les sources
  partagées mais non définies : DAS (Test004)" liste chaque variable qu'une source partagée active
  utilise et qui n'a pas de ligne, avec la source qui l'utilise.
- **Un clic ajoute la ligne.** Le bouton "Ajouter DAS" ajoute une ligne nommée `DAS` avec une valeur
  vide et place le curseur dans la case Valeur. Rien n'est enregistré tant que vous n'enregistrez
  pas la page.
- **Nom et valeur, expliqués.** Le Nom est ce que le fichier écrit entre crochets (`DAS`) ; la
  Valeur est votre propre identifiant (`jdoe`). Le guide le montre maintenant avec un exemple.

## Notes de mise à jour

- **Le rapport contient moins de lignes.** Une source qui affichait 79 avertissements pour une seule
  variable manquante en affiche 1. Copier et le CSV gardent une ligne par session : un script qui
  lit le CSV n'a rien à changer.
- **Une ligne avec un nom et une valeur vide compte comme définie.** La carte ne liste plus cette
  variable ; c'est la ligne elle-même qui demande une valeur.
