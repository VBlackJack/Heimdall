# L'outil Ports ouverts relit une table qui grandit pendant sa lecture

Une petite version de maintenance. Une correction se voit, dans l'outil Ports ouverts ; le reste
rend plus robuste la façon dont Heimdall lit les tables de connexions du système et modifie cinq
tests du projet : quatre perdent une cause connue d'échec intermittent ou de blocage, le cinquième
donne seulement plus de détails quand il échoue. En dehors de la vérification des tunnels Plink
décrite plus bas, rien ne change dans la façon dont les sessions se connectent.

## Ce que vous verrez

### Outils

- **Ports ouverts relit une table qui grandit pendant la lecture.** L'outil lit quatre tables de
  Windows : TCP et UDP, chacune pour IPv4 et IPv6, et les affiche en une seule liste. Pour
  chacune, il demandait à Windows la taille de la table, puis la lisait une fois à cette taille.
  Si une connexion ou un socket apparaissait entre les deux étapes, la table ne tenait plus, la
  lecture échouait, et les lignes de cette table étaient laissées de côté sans un mot : par
  exemple toutes les lignes TCP IPv4 absentes jusqu'à un nouvel appui sur Actualiser (l'outil ne
  s'actualise pas tout seul). L'outil relit maintenant la table à la taille que Windows indique
  alors, au plus quatre lectures en tout ; si la table est encore trop grande après la quatrième,
  ses lignes sont laissées de côté comme avant.
- Le même outil refuse maintenant une table dont le nombre de lignes annoncé dépasserait la
  mémoire remplie par Windows ; avant, il lisait ce nombre de lignes quand même. Les lignes d'une
  telle table sont laissées de côté, comme pour toute lecture en échec. C'est une précaution :
  aucune table de ce genre n'a été observée.

### Tunnels SSH par Plink

- Quand un tunnel est démarré par Plink, Heimdall vérifie qu'une écoute sur le port transféré
  appartient au processus Plink qu'il a lancé. Cette vérification lisait la table TCP de la même
  façon. Quand cette lecture échouait, la tentative restait sans conclusion et la vérification
  recommençait un intervalle plus tard (deux secondes par défaut) : un tunnel bien ouvert par
  Plink était accepté plus tard au lieu d'être interrompu, sauf si la lecture échouait à chaque
  tentative ; un tunnel interrompu parce qu'un autre programme tenait le port pouvait être
  journalisé avec une raison moins précise. La lecture est maintenant retentée de la même façon.
  Le message affiché quand la vérification ne passe pas est inchangé : "L'exécutable Plink
  configuré n'a pas ouvert lui-même le port transféré. Le tunnel a été interrompu."

## Comment cela a été vérifié

- Par des tests automatisés qui donnent au lecteur de Ports ouverts, pour chacune de ses quatre
  tables, une table dans la vraie disposition de Windows qui grandit une fois, qui grandit à
  chaque tentative, ou qui échoue pour une autre raison, et qui font de même pour la table IPv4
  de la vérification des tunnels (sa table IPv6 seulement pour une croissance unique). Ils
  vérifient aussi, par un allocateur de substitution, que chaque bloc de mémoire pris est rendu.
- Sur un vrai poste : un test qui exécute le vrai code de lecture de l'outil a renvoyé des
  lignes. La fenêtre de l'outil elle-même n'a pas été ouverte.
- La suite de tests du projet est passée sur le poste du développeur et dans la construction
  automatisée de chaque changement.
- Non reproduit : la panne elle-même. Elle demande que la table grandisse entre deux appels
  système, ce qui n'a pas pu être provoqué à la demande.

## Notes de mise à niveau

- Rien à faire. Aucun réglage, aucune donnée enregistrée et aucune dépendance ne change dans
  cette version.
- Si Ports ouverts affichait une liste qui semblait trop courte sur un poste avec beaucoup de
  connexions, un nouvel appui sur Actualiser ramenait en général les lignes ; cette version rend
  ce besoin beaucoup moins probable, sans l'exclure.
